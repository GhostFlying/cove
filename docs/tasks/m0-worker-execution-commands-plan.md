## Ordered pump and finite accounting

The module-private per-run pump is the single sequence/admission authority for native output, ordered commands, T2 apply and exit. A queued command establishes a transaction boundary before later native ingress receives a sequence. Later callback bytes, including bytes emitted synchronously by `native.resize`, remain copied and **charged but unsequenced** until the transaction's native resize → settled T2 resize → optional appearance → control facts complete; then they receive fresh increasing sequence numbers and are parsed. No renumbering of already admitted facts, second command queue that bypasses output, or uncharged callback retention. Rejected/no-op commands cannot consume a sequence or leave a hole. `receivedSeq` records only actually allocated facts; `parsedSeq` advances after T2 settlement. Query/focus replies still enter the same bounded N2 FIFO synchronously at the model observation point and never wait on their triggering parse promise.

The worker admits at most `effectiveBudgets.maxRuns` distinct live **or retained** run IDs, capped by `M0_LIMITS.maxRuns = 128`; normal native owner release does not erase a retained identity. Across the worker, queued or executing commands are limited by `effectiveBudgets.pendingWorkerCommands`, capped at 256, and every copied payload, deferred ingress byte, queued command and retained identity record is charged to `effectiveBudgets.workerBytes`, capped at 64 MiB. Source per-run parse high/hard caps and N2 writer byte/task caps remain additional limits, not substituted by worker accounting. Retained input authority keys have a finite worker-wide count capped by the same pending-command limit and charged record bytes; cap exhaustion returns existing bounded busy/rejected semantics without LRU eviction that could admit duplicate run or input identity. At implementation time tests must identify the exact byte charge and release points for these existing budget fields; no wire budget field or persistent operation ledger is added.

## Command transaction rules

At execution, revalidate command worker/run/request identity, complete holder (`connectionId`, `viewId`, `subscriptionId`), current epoch and canonical spawn payload. One live or retained `RunRef` cannot spawn again; duplicate pending request IDs are rejected. A non-null fresh control grant uses checked `expectedEpoch + 1`; a positive-epoch release preserves epoch and clears holder. Same-size geometry performs no native/model resize. A changed geometry applies native resize first, then settled T2 resize, optional appearance and control; accepted `atSeq` is the complete transaction boundary. Presence/1004 changes only on null↔non-null holder transition; replacing holder A with B does not invent blur/focus. Partial native or T2 failure does not claim rollback or a successful grant; it fences subsequent writable control/input but preserves status, stop and actual liveness evidence.

Input rechecks full subscription, current holder/epoch and strictly newer `inputSeq` at execution. Gaps in newer input sequence are valid; duplicate/lower values and stale authority fail before N2. The highest admitted/attempted input sequence for the same full subscription identity remains retained across loss and regain of control; a new identity has its own counter. Reserve the complete byte/task intent before handoff, call N2 submit once, and distinguish admission from `writerCompletion`: only actual positive settled bytes may populate `writtenBytes`. Zero-prefix, partial or uncertain completion uses the accepted `RESULT_UNKNOWN`/`inspect-run` response without retrying the remainder. Automatic model replies bypass only user focus authorization, never the N2 FIFO or its limits. Genuine user input is not filtered by escape-content guesses.

Status uses a settled T2 snapshot or the same pump barrier to return the existing `RunStatus` with actual geometry, control, received/parsed sequence, recovery and `live`/`unverifiable`/`exited` truth. Stop reuses the cached bounded N2/session receipt; stop accepted does not prove exit and late leader/writer facts may improve a later snapshot without rewriting the earlier receipt. Native owner release still requires directly owned leader exit plus writer closure; initial-group helper cleanup remains best effort and helper unknown alone does not hold quota. `shutdown` stops admission and attempts disposal for every known session without short-circuiting or serially multiplying each bounded stop deadline; retained uncertainty stays visible.
