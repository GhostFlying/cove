## Public and owned seams

- `WorkerRunSessionCapability` gains ordered `captureBaseline()` and `capturePreview()` methods. Each operation is one item in the existing per-run pump, not a `barrier().then(capture)` pair. A capture item settles the model's public `TerminalModel.captureBaseline()` or `capturePreview()` before the next fact; the baseline item's settled `atSeq` defines the post-N retention boundary. RunSession calls an internal immutable parsed-fact retention observer before the external diagnostic `onFact` callback.
- Worker execution retains one replay window per run and one bounded route record per full `SubscriptionRef`. `execute(PipeCommand)` remains the public command entry. It adds a package-local synchronous delivery port supplied by `runWorkerPipe`, with `admit(event,payload,token)` returning accepted/blocked/closed, cancellation of unsent token frames, marker-enqueued activation, physical release/capacity wakeup. The endpoint's single FIFO and callback/close accounting own physical frames. The worker owns route attempts, logical sent boundaries, capture leases and deadline state. A direct-execution test sink implements the same port.
- `subscribe/recover` reserve the next attempt, capture/replay, and return a correlated result while the new producer is fenced. The endpoint queues the result marker before invoking the checked activation callback. Same-ref recover first applies older ACK/progress, invalidates the old token and cancels only unsent old frames. Transport-owned old bytes remain FIFO and charged. `unsubscribe` fences first, returns after route retirement; its correlated physical result settlement (or pipe close) releases the tombstone proof. No client-facing new opcode or invented error is introduced.
- `applied-ack/baseline-progress/unsubscribe` are class X, serialized end-to-end. `status` and `stop` keep independent class S/T slots. Preview uses current-screen capture and emits complete start/chunk/end before its correlated result. Installed subscription is required for subscription-bearing input/resize/appearance; input readiness requires final current-attempt ACK.

## Finite resources and ownership

Let B=`pendingWorkerCommands`, P=`pipeQueuedBytes`, C=`reservedControlBytes`, Q=`HEADER_BYTES+MAX_METADATA_BYTES=4112`, M=`MAX_METADATA_BYTES=4096`, K=`128+2M=8320`, A=`authenticatedSockets`, S=`subscriptionsPerConnection`, R=A*S. Endpoint/execution request identities: O<=B, S<=1, T<=1, X<=1, total<=B+3. X is the existing rejection/duplicate extra slot, never an additional fifth partition. One not-yet-admitted raw metadata-only X frame, <=Q and charged within ingress P, may wait for physical X release. At C=Q only one S/T/X reply reserves Q at serialization time; persistent round-robin chooses the next eligible class. Ordinary physical bytes plus reserved replies <=P-C; all physical/reserved bytes <=P; callback or actual close alone releases physical debt. A logical ACK cannot do so.

One route record reserves K, one connection record K, and the endpoint/execution X canonical copies reserve up to 2K from the existing `workerBytes` pool before first W2 route. Minimum new metadata headroom is 4K=33280; maximum configured default route+connection+X is `(R+A+2)K=4542720`, on demand. Active, admitting, tombstone and retiring routes together <=R and <=S per connection; connection records <=A. Retention ring <=`replayBytes` and <=`replayEvents` per run; post-N <=`postNBytes` and <=`postNEvents` per route; subscription credit <=`subscriptionCreditBytes`. Payload, frame encoding, transfer copies and scratch are charged separately before allocation. No timer eviction of unproved tombstones; unsubscribe response settlement or actual pipe close proves retirement. No forever identity set.

Class X includes recover as well as ACK/progress/unsubscribe, since a deferred earlier ACK must complete before the same-ref recover fence. A later X frame remains one bounded raw metadata-only parked frame while the earlier X result is physically unsettled; it cannot bypass that result through the ordinary lane. Subscribe for a fresh ref and preview remain ordinary. The worker's X request identity and metadata lease live through response settlement. Before a recover fence, reject an explicit cursor lower than the route's proven applied cursor; an omitted cursor chooses baseline but retains the proven lower bound until the new baseline is committed.

For a public baseline copy the worker must acquire a lease for at most `baselineVtBytes+baselineTailBytes` plus bounded descriptor representation before invoking the engine operation; internal engine checkpoint scratch remains independently leased. For preview, the model constructs chunks and final VT inside its public call, so the author must establish a conservative preallocation bound under the fixed max geometry/preview cap or request the narrow engine lease extension before implementing that path. Two generation slots and four preview slots use a worker-local finite scheduler; acquire the slot before adding a capture item to the run pump. Capture/replay/preview frames never consume control C. A route scheduler sends at most 32 frames or 256 KiB per turn and yields, rechecking token after every callback. Its producer does not await Writable drain or subscriber parse inside the run pump.

## Narrow engine preview scratch extension (root-granted after initial plan)

Root granted only `terminal-engine/src/terminal-model.ts`, `terminal-preview.ts` and direct engine tests after the off-tree `engine-capture-lease-request.md`. Existing `createScreenPreview` builds a row string, encoded chunks, and a final copy before checking the byte cap, so the worker's final-result lease alone cannot cover its opaque scratch. Replace this construction with one `Uint8Array(B)` working buffer, where B=`previewBytesPerRun`<=65536, and `TextEncoder.encodeInto` each fixed sequence, SGR, and existing cell text directly into its remaining slice. On any incomplete `encodeInto` read, reject the whole preview; no string concatenation or encoded chunk allocation is permitted. `output.slice(0,used)` is the sole detached result allocation. The known SGR/position strings have fixed profile bounds; the helper may examine an existing cell string but never duplicates an unbounded row.

The worker pre-reserves B for the final detached result before entering the public capture. The engine, inside the queued operation before allocating its working buffer, reserves `B + 512*cols*rows + 256` through its already supplied `reserveRetainedBytes` callback. This deliberately bounds the B-byte working buffer plus transient per-cell view/attribute/SGR objects (<=4800 cells under the effective max geometry, with 512 bytes per cell) and fixed metadata. The worker lease covers the final detached `used<=B` copy. Both coexist during `slice`, so peak attributable preview allocation is bounded by `2B+512*cols*rows+256`; only the working/scratch portion is charged to engine, only the detached result to worker. On reserve denial return existing `unavailable` before calling the helper; release engine scratch in `finally` on success, oversize, throw or disposal. Worker retains its lease after success, shrinks it to actual VT length and releases it after the terminal result barrier; on failure it releases immediately. Existing model state/engine checkpoint leases are separate. Public method signature and wire/profile/query/preview cap remain unchanged. Engine tests exercise denial-before-construction, large cell oversize, legal exact bytes, and throw/lease release; worker consumer tests exercise final ownership and two overlapping captures.

## Exact detached baseline reservation correction

The first author-local W1 pressure retake proved that a fixed `baselineVtBytes+baselineTailBytes` worker lease rejects a 256 KiB run before its actual small baseline can be captured. Keep the original pressure budget and physical-byte assertions. Extend only the granted public `TerminalModel.captureBaseline` and the ordered RunSession capture operation with an optional caller-owned reservation callback. After the engine has refreshed its checkpoint and computed exact `checkpoint.vt.length + tail.retainedBytes`, but before either detached copy, it invokes the callback with that exact sum plus 4096 bytes for bounded descriptor/transfer metadata. A false result returns existing `unavailable` without copying. The worker callback acquires one lease, stores it on the current route, and owns release on every success, denial, throw, token fence, and shutdown; the engine never releases a caller lease. Existing callers omit the callback and preserve their API behavior. This charges only actual detached baseline bytes while engine checkpoint/scratch/tail leases remain separate. The worker shrinks the lease after capture to `vt.length + tail.length + 4096`; no double-counted copy or allocation-before-reservation is permitted.

The callback is synchronous, invoked at most once in the model's queued capture item, and returns true only after the caller owns an exact-size lease. It cannot return a mutable byte view and receives only an integer, so it cannot change the checkpoint or tail. Any synchronous reentry may enqueue a later model operation but cannot interleave with the current capture's no-await reserve→copy section. Re-check disposal after callback before copying; callback denial, throw, or disposal returns an unavailable/disposed result, never faults the authoritative model. If a callback acquires a lease and then throws, that caller remains responsible for its own release; the worker's callback acquires and returns without user code between those steps. The worker also re-checks route token/state after its ledger call and immediately releases if it was fenced reentrantly. On any capture failure or rejected descriptor, its route fence releases the lease. Successful VT and tail are newly detached byte arrays; the route keeps the charged lease until final parsed ACK or fencing, while the pre-existing model checkpoint and tail retain their separate engine leases. Existing zero-argument public callers are unchanged. The direct engine negative controls will prove denial/throw/dispose before detached copy and unchanged model state; worker controls will prove exact lease held across transfer, then released and low-budget W1 pressure unchanged.

Capture deadlines begin before the queued model operation. A baseline wait races its monotonic deadline; expiry fences the token and the exact reservation callback must decline if it eventually runs. For preview, expiry may settle the command before the engine's queued capture promise resolves, but the final-result lease and one active job slot remain charged until that promise settles; its late resolution is fenced from publication. This preserves bounded memory ownership without treating a timeout as proof the model stopped. A callback or delivery-port throw yields a correlated failure and releases only its own owned leases. A reentrant capacity callback cannot send the same frame twice.
