## One routing decision before dispatch

The frozen `ByteFrame` (`packages/protocol/src/provisional/frame.ts`) carries only class/metadata/payload. `RunEventSchema` (`terminal-events.ts`) contains run and seq for output/resize/control/appearance/exit, but no subscription identity. `TerminalEventSchema` embeds these directly. `SubscriptionRef` exists on commands/results and baseline transfers. This creates two concrete ambiguities:

1. A and B subscribe to the same run through one connection, at different recovery positions. Two `output {run,seq:7}` frames cannot be routed to their intended view, nor distinguished from a duplicate for A. The payload is not a reliable route key.
2. A recovers to replacement B. A delayed A output at N+1 after `recover-result` is indistinguishable from B's first N+1 output; validating run/seq alone cannot fence the old subscription. A local callback token cannot invent the missing wire identity.

These are failures of the already intended independent subscriptions/generation isolation, not requests for more product capability. Do not silently restrict the server to one subscription per run or weaken stale-frame acceptance.

| Option                                                               | Concrete change and tradeoff                                                                                                                                                                                                                                                                                                                                                                                                                              |
| -------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1. Connection-local restriction plus replacement barrier             | Client uses at most one subscription for a run on a socket, and server guarantees no old-subscription frame after a recover-result barrier. Two pages can use separate sockets. Smaller source change, but adds a global ordering obligation and constrains later multiple same-run views; not derivable from present schemas alone.                                                                                                                      |
| 2. Dedicated view connections and fresh connection on every recovery | One view per socket; close/fence old socket, negotiate and attach afresh instead of in-place recover. No wire change, strongest simple isolation, but consumes authenticated socket budget (32 total), adds handshake/recovery churn and leaves same-socket recover unused. 100 live PTYs do not mean 100 live views, but this is a poor permanent multiplex foundation.                                                                                  |
| 3. Explicit external subscription delivery, recommended              | Keep worker `RunEvent` run-scoped and wrap its external delivery with `SubscriptionRef`, e.g. a closed `run-event` terminal event carrying `{subscription,event:RunEvent}` and the existing single payload. Validate outer subscription.run against inner event.run and negotiated connection. Every view/replacement has an unambiguous route; runtime can broadcast the same immutable inner fact to multiple subscriptions. No renderer or PTY change. |

For option 3, the sole protocol writer owns `packages/protocol/src/terminal-events.ts` (new external delivery schema/type), `terminal.ts` (class-3 validation/payload allowlist/binding and exports), and any directly affected explicit event-type use in `pipe.ts`/`runtime.ts`. Preserve the existing inner `RunEvent` and renderer `TerminalEvent`/`TerminalView.applyEvent` shape; pipe/runtime continue carrying run facts, not client routes. External terminal validation may use a separate external-event union rather than making engine/pipe consumers unwrap an external route. Baseline start/chunk/end already have subscription refs and need only consistent routing checks. Preview stays correlated separately and must never be mistaken for live stream data.

Update terminal fixture/manifest and compiled protocol consumer/terminal/composition/boundary tests together; add two same-run subscriptions with differing cursors plus a late old-replacement N+1 counterexample. P2 then assigns envelope refs from authenticated subscription state, P3 validates/unwraps them, V1/T2 semantics remain unchanged. Review exact effective framed sizes after wrapping; the 4096-byte metadata cap still applies before send. This is one bounded schema/fixtures correction plus two later consumer mappings, more immediate work than option 2 but smaller long-term burden than implicit socket ownership. Transport ports are local TypeScript interfaces in client, not new wire contracts or framework adapters. HTTP accepts a bounded POST descriptor (path, plain headers, body bytes, response byte cap) and returns status/headers/body plus a cancellation handle; actual `fetch`/Node HTTP lives in H1. Terminal transport opens an ordered message channel, reports bounded text bootstrap or one complete binary frame per message, accepts bounded string/Uint8Array writes, reports local acceptance (`not-sent`, `handed-off`, or `unknown`) and close, and disposes idempotently. A `handed-off` write is not a server/PTY ACK. An adapter must report inability to bound its queue instead of buffering indefinitely. Callbacks carry a locally allocated attempt token captured before opening; no server field substitutes for that token.

Use injected `encodeUtf8`, fatal `decodeUtf8`, opaque-ID generator and scheduler (`nowMs`, cancellable timer, yield-turn). Public and implementation code compile with ES-only libs and no Node/DOM globals: no `URL`, `AbortSignal`, `Buffer`, `WebSocket`, `TextEncoder`, global timer types, native/xterm imports or direct process/environment reads. Uint8Array/Promise are allowed. H1 supplies platform primitives; tests supply controlled fakes. Do not implement an extra UTF-8 engine solely to avoid injection.

## Bootstrap, RPC and outcome rules

A successful HTTP bootstrap validates bounded/fatal JSON, bootstrap/protocol/profile/encoding, capability intersection, effective budgets, and expected server/instance. Different build is diagnostic only. A terminal connection independently bootstraps; business frames before success or success without connection ref fail closed. Changed instance preserves old run refs and displays mismatch/unverifiable, never rebinds to a new run or starts a replacement server. Unknown/malformed bootstrap is not fed to the business decoder.

Credentials come only from the injected supplier. HTTP authorization and terminal first-message secret are private transport material, never URL, public state, diagnostics or fixtures. Terminal bootstrap is bounded by 8 KiB/5 seconds; input deadlines use monotonic injected time, not wall-clock ordering. Validate server effective ceilings rather than silently replacing them with local maxima. Every HTTP call reasserts negotiated identity/protocol and validates response binding before interpreting RPC data. H1/P2 must agree the concrete identity-header mapping through frozen bootstrap constants; no consumer-specific credential or Origin workaround.

Reuse `validateRpcResponse`, method params/results and `validateRpcResultForCall`, plus explicit negotiated server/instance binding for all returned run records. Match request ID, method, operation ID and run. Separate network completion from operation.state completion. For a create/stop call whose response is lost after possible send, emit `RESULT_UNKNOWN`/`query-operation` with the original operationId; never automatically repeat or mint another ID. An explicit caller resubmission must preserve canonical method/intent/instance/operationId. Only an explicit returned failed record is failure of an accepted operation; timeout is not proof of non-execution. Keep bounded in-flight entries, not a second permanent receipt ledger; caller retains unresolved operation handles. Input unknown uses `subject:'input'`, `nextAction:'inspect-run'`, and has no operation receipt.

## State and ordering invariants

Keep connection, subscription, view, control and execution evidence as separate domains. Suggested connection states: idle/negotiating/connected/unverifiable/incompatible/disposed. Subscription states: detached/attaching/installing-baseline/replaying/ready/recovering/unavailable. Control tracks none/pending/granted with epoch/grant boundary and latest local focus intent. Execution evidence uses exactly live/unverifiable/exited; confirmed exit remains historical fact even if the connection later closes. Do not infer exit from failure, empty UI, timeout, RUN_NOT_FOUND or instance mismatch.

Maintain four independent fences: connection attempt token, server ConnectionRef, SubscriptionRef and local viewGeneration. Check them on receipt and again after every await/parser callback/timer; request IDs alone do not authorize delivery. Increment checked counters with `nextCounter`; exhaustion returns COUNTER_EXHAUSTED and invalidates the affected session instead of wrapping/resetting or spawning. A fresh connection/subscription may establish its own counter scope. Mutable input and payload arrays must have explicit ownership; copy once on admission where the caller can mutate them, release after parse/result, and never retain an arbitrary oversized backing buffer through a small subarray.

## Focus, input and renderer agreement

V1 planner `/root/m0_v1_plan` and P3 agreed against the exact frozen `TerminalView`:

- P3 alone owns the ordered pending payload queue and all wire cursor/ACK/control/request IDs. V1 executes one awaited parse operation at a time, defensively rejects overlap, and never adds an independent output backlog.
- `initialize` with strictly newer viewGeneration on a retained object invalidates old parser/input/focus/failure closures and creates a fresh guarded backend. `beginBaseline` operates on fresh restoration state. `onFailure` has no generation field, so listener closure ownership is also fenced. Disposed/replaced callbacks cannot regain authority. V1 may emit advisory INPUT_REJECTED for a too-large paste before producing any InputIntent; P3 reports that rejection without inventing an input ID/receipt or discarding a sound model. Only renderer-integrity/recovery failures invalidate the model.
- V1 emits qualifying real focus intent synchronously before its input intent for a spectator typing/paste or input-producing pointer interaction. Plain selection/copy/scroll does not claim control, even if xterm internally focuses its textarea; keyboard/tab focus and explicit host input-target activation may claim. H1 has an explicit requestFocus/setInputTarget path for deliberate activation independent of selection. Adapter has no offline/input replay buffer. Its focusSeq is monotonic per viewGeneration; P3 translates accepted local intents to a separate monotonic wire focusSeq in connection/view scope. Gaps are valid; duplicate identical local intent is ignored, conflicting duplicate/older intent cannot override newer state.
- V1 `applyEvent(control)` must find the authority geometry already consistent with preceding ordered resize; it does not add another resize. P3 intercepts requiresBaseline resize. Authority appearance changes arrive in ordered events; observer preferences cannot mutate server facts.
- `setVisibility(true)` never focuses. A real focus loss caused by hiding may emit focused:false; P3 blurs only its own current epoch. Measurement changes alone emit no focus. V1 measures via ResizeObserver; H1/platform caller invokes `requestResize(view.measureGrid())`, which sends only with a current ready grant.
- V1 retains query suppression/provenance in live/baseline/replay and emits only keyboard/paste/mouse user intents. P3 must not infer a reply from byte grammar: legitimate pasted reply-looking bytes still count as user input. Server mode-1004 focus reporting is not forwarded as client input.

Readiness for input is the conjunction of current negotiated connection, active ready subscription/model, current local foreground input target, a matching latest focus result, and **appliedSeq >= grant.atSeq** with ordered control facts still identifying this subscription at that epoch. A focus result cannot outrank a newer observed control event, newer local focus request, blur, connection or generation. Recheck epoch/admission immediately before every queued chunk is handed to transport. Local desired focus does not override server facts. Losing control never starts a focus loop; only explicit user interaction or permitted foreground reconnect policy can request it again.

Keep input bytes while waiting for a focus grant only if the input came after a current explicit focus intent while the existing model was ready. Bound this staging with the same input budget, retain its focus-intent token, and reject it if the grant fails/times out, target changes, control changes incompatibly, or recovery/disconnection starts. Do not retroactively attach old staged input to a new focus attempt. Ordinary asynchronous output parsing while already ready does not globally suppress genuine input. Baseline/replay synchronization itself is non-admitting; report an explicit input rejection rather than silently discard or replay after recovery.

Each admitted wire input frame gets a fresh inputSeq within its subscription (strictly increasing, gaps allowed). Preserve exact binary bytes and source attribution locally; payload is not transcoded or merged with unrelated intents. Split admissible input into bounded frame chunks and expose per-intent written prefix and remainder outcome; no atomic-paste claim. Total retained unsent/in-flight input is <= negotiated inputQueueBytes (64 KiB ceiling) and metadata/pending limits below. Oversized one-shot intent is rejected before any bytes are sent; H1/CLI can submit a large paste in explicit bounded chunks, awaiting prior outcomes. If a chunk is rejected/unknown or epoch changes, stop sending subsequent queued chunks for that intent and clearly report written prefix/unknown portion/not-sent remainder. Never auto-resend any inputSeq after lost result/reconnect.

A matched `input-result` must have correct request/run/subscription/epoch/inputSeq and writtenBytes equal to that frame's actual payload length before claiming all bytes written. A schema-valid shorter count is not full success: expose its count and uncertainty for the remainder, stop the intent and inspect the run. No claim that shell/agent executed the bytes follows from written. Unknown settles pending consumers once; a late response may be ignored after the request's bounded lifetime, never resubmitted or rebound to another request.

On reconnect, prior foreground/focused state is merely desire. After synchronization, reapply focus once only when host policy still explicitly marks the controller foreground and the input target; hidden/background controllers recover only subscriptions. Old grant/input/focus callbacks remain invalid. New view/replacement does not inherit focus merely because the prior view had it; host must restate the target or emit a real intent.
