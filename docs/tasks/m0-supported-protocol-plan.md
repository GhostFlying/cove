## Common encoding and identity

Keep P1a's CP 16-byte header, reserved-zero bytes, big-endian uint32 metadata/payload lengths and pull-decoder limits. Frozen M0 terminal uses lane **3**, pipe lane **4**, each revision **1**; provisional lanes 1/2 remain revision 1. This makes accidental probe/production mixing fail explicitly. Frozen lanes use four framing classes: command=1, result=2, event=3, error=4; a closed metadata `type` discriminant identifies the exact table entry. Do not overload provisional kind meanings. Pipe bootstrap also uses its bounded lane format; it is not external bootstrap or JSON-RPC.

Exact frame schemas/code allocation tables, not prose alone, are the frozen downstream source of truth after implementation. Limits remain 16-byte header, 4096 metadata bytes, 65,536 payload bytes, 69,648 complete-frame bytes; 32 frames / 256 KiB input and emitted bytes per pull, one owned incomplete frame. Payload-bearing variants alone allow bytes; header class and metadata type must agree. Host composition checks fatal UTF-8 for metadata/JSON payloads (never for opaque VT), JSON structure (depth 16 / 4096 structural tokens), schema, identity and payload length before delivery. Unknown optional fields are ignored after size/structure checks; unknown required discriminator/opcode, lane/revision, invalid integers or reserved bits are fatal. No resync scan. Each WS binary message carries one complete frozen terminal frame; pipe ingress permits arbitrary split/coalesced frames. The decoder remains reusable and independent of scheduling.

`RunRef={serverId,relayInstanceId,runId}` and `WorkerRef={serverId,relayInstanceId,workerId,workerIncarnationId}` retain opaque ASCII IDs (1–128 characters). Add `ConnectionRef={connectionId,generation}`, `SubscriptionRef={run,connection,subscriptionId,viewId}`, all explicitly validated. Server allocates connection ID/generation on authenticated WS establishment and never reuses an ID in the instance; client view generations additionally fence adapter callbacks. No PID/address/build equivalence. Worker+run server/instance fields must match and runtime verifies the actual run→worker-incarnation route.

All counters are finite safe integers; zero means initial state only, emitted run events start at 1. One worker assigns contiguous per-run `seq` to output, resize, control/appearance changes and exit, in execution order; a published output boundary is parsed, not merely received. Counters for focus, input, operation revision and event sequence are different fields/scopes. Pure checked increment fails at MAX_SAFE_INTEGER, never wraps or clamps. Connection/focus/input exhaustion requires a fresh connection/subscription; epoch or run-seq exhaustion fences further control/stream delivery with `COUNTER_EXHAUSTED`, preserves PTY ownership/model processing and reports delivery unavailable. It does not invent an exit, reset the counter or automatically respawn. Runtime can still explicitly stop the bound run. Overflow tests use injected counters, not huge loops.

## T-profile and P-terminal recovery

Profile identity is `pragmatic-logical-grid-v1`; baseline encoding `vt-checkpoint-tail-v1`. It is independent of xterm version. Current pins remain headless/browser 6.0.0 and serialize 0.14.0 as implementation diagnostics, never wire admission identities.

Required: ordinary visible logical-grid cells/effective styles, current cursor/pen/charset/input modes, supported saved position/modes, common continuation, Unicode/wrap, budgeted normal history/content and alternate content/switch/exit, parser/UTF-8 tail, source purity, server-only query authority, ordered N/N+1 recovery and bounds. Explicit non-gating diagnostics: saved SGR/charset fidelity, retained off-grid characters/mixed physical-row topology and their special edit continuations. No exception for ordinary visible loss/garbling. Real agent qualification is `integration-obligation`, not a successful headless assertion. No fake same-grid resize; all client types use the same normal+alternate recovery.

Freeze the following data; baseline metadata contains no cells or engine-private state:

- `Geometry={cols,rows}`; `Coverage={normal:{historyLines,includedHistoryLines,trimmedBefore,resizeContext:'complete'|'requires-baseline'},alternate:{included:true,resizeContext:...}}`. `trimmedBefore` is a boolean, not an invented permanent history index. `includedHistoryLines<=historyLines<=effectiveHistoryLimit`; normal current content and required alternate content cannot be omitted to satisfy a budget.
- `BaselineDescriptor={baselineId,run,subscription,profile,encoding,checkpointSeq,atSeq,captureGeometry,currentGeometry,coverage,vtBytes,tailBytes,chunkCount}`. `checkpointSeq<=atSeq`; bytes are fixed before first chunk. `captureGeometry` is the checkpoint geometry; `currentGeometry` is the boundary N geometry. M0 encoding requires these geometries equal; a different geometry requires a new checkpoint after the true authority resize, not a hidden receiver-size trick.
- Baseline byte order is checkpoint VT then raw tail, divided using exact `vtBytes`/`tailBytes`. Tail comprises the original output bytes since a proved checkpoint through parsed boundary N; no transcoding, truncation, duplicate C0 effects or synthetic PTY reset. A checkpoint refresh after ordinary printable output keeps it bounded. Cross-geometry recovery must obtain a fresh source checkpoint; do not mislabel resize-spanning bytes as an output-only tail. T2/W2 explicitly test a resize around split UTF-8/CSI and checkpoint readiness; bounded waiting may expire, but ordinary valid fixtures cannot be permanently classified unsupported to evade recovery.
- `baseline-start` descriptor; `baseline-chunk` carries baselineId/subscription, ordinal and payload; `baseline-end` repeats baselineId, counts/total and N. Start/chunks/end bind one descriptor; chunks start at 0, contiguous, no duplicates, exact total, no live-event interleaving within that subscription's transfer. Other runs/subscriptions may interleave. End without complete accounting fails; no preallocation based solely on untrusted declared totals. Ordered reliable framing/counts suffice; no new checksum dependency.
- Runtime/worker atomically fix N and reserve post-N events before exposing the baseline. Controller may stream installation into a **fresh, non-admitting** backend; failed/expired install disposes it. Only end plus all parse callbacks permit ACK N and input readiness; then N+1 follows. Bound concurrent transfer and post-N retention. Old generation/baseline callbacks cannot ACK or release a newer stream.
- `recover` has `resume:{appliedSeq,profile,encoding,geometry}` only when the actual local model is retained. Replay is legal only for matching complete identities/profile and contiguous retained events. Otherwise a new subscription/baseline is required. Gap/expired recovery never continues the old stream. An ordered resize event includes resulting geometry and `requiresBaseline`; if either buffer lacks context, invalidate the current subscription at that boundary and recover a fresh source-grid baseline. No observer-local fit changes logical columns.

Queries: publish a table mapping VT selectors, state source and required support to authored fixture IDs. Initial positive server claim is the Q1/T1 **intersection**: DSR status, CPR, DEC CPR, primary/secondary DA, tested DECRQM, OSC foreground/background and indexed palette queries for explicitly known indices. Unknown appearance values produce no invented reply. Foreground/background are RGB16 triplets; palette is a bounded list of unique `{index:0..255,rgb}` entries. Seed the tested white/black/palette-1 values; advertised `knownPaletteIndices` states actual support. Clients may submit validated appearance with current epoch; worker applies it in run order. OSC setters/mixed set+query must preserve their state effects; live setters update authoritative appearance, reconstruction never sends replies to PTY. Freeze exact tested replies as fixtures, not assertions that every selector parameter is supported. Q1-only cursor-color, DCS status/margins and window reports remain suppression-tested but are not advertised as proven headless support; T2 may qualify them with explicit engine tests before advertising the already-defined optional capability.

Q1 established that public whole-sequence suppression loses mixed OSC setters. P-view therefore reports only provenance-qualified keyboard/paste/mouse bytes; all emulator automatic output is excluded in live/replay/baseline phases. Automatic focus-in/out is separately classified (not called a query). M0 worker derives mode-1004 focus reports from effective control presence transitions: no-controller→controller sends focus-in, controller→none sends focus-out, controller A→B sends neither; disabled mode sends neither. Never forward observer DOM focus reports. T2/W1 must test this rule before runtime claims it; no extra wire input source or client reply authority is introduced.

## Commands, results and ordering

Every terminal command has requestId plus complete applicable refs. Request correlation is not deduplication or an execution receipt. Frames below have empty payload except `input`, `output` and baseline/preview chunks. Result/error echoes command type/requestId and applicable identities.

| Command                 | Required fields / result                                                                                                                                                                                                                                                   |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `attach`                | run, viewId, profile/encoding, optional retained-model resume; result new SubscriptionRef and recovery mode/boundary. Starts recovery, never focus.                                                                                                                        |
| `detach`                | subscription; result detached. Invalidates only this subscription and releases its control if held, without PTY stop. Already-detached same identity is harmless while the bounded connection tombstone remains; no tombstone is treated as a new subscription.            |
| `recover`               | live subscription and reason (`gap`, `released-view`, `resize-context`, `expired`), optional valid resume; successful in-place result preserves the complete SubscriptionRef and returns recovery mode/boundary. A new attach after retirement allocates a fresh identity. |
| `focus`                 | subscription, focusSeq, measured geometry, optional known appearance; result effective control state, epoch and `atSeq`.                                                                                                                                                   |
| `blur`                  | subscription, epoch; result effective control state/boundary; stale blur cannot release another controller.                                                                                                                                                                |
| `resize` / `appearance` | subscription, epoch and new geometry / known appearance; result applied boundary. Same geometry creates no extra PTY/model resize.                                                                                                                                         |
| `input`                 | subscription, epoch, inputSeq; 1–64 KiB opaque bytes; result inputSeq, epoch, `status:'written'`, writtenBytes. Errors distinguish rejected-before-write from unknown result.                                                                                              |
| `applied-ack`           | subscription, appliedSeq; result optional correlation acknowledgement, never a fresh control grant.                                                                                                                                                                        |
| `baseline-progress`     | subscription, baselineId, last fully parsed chunk index; releases transfer credit only, never advances appliedSeq/readiness.                                                                                                                                               |

Run facts are `output {seq}`, `resize {seq,geometry,requiresBaseline}`, `control {seq,epoch,holder:null|{connection,viewId,subscriptionId},geometry}`, `appearance {seq,appearance}`, `exit {seq,exitCode:number|null,signal:string|null}`. Baseline transfer, input results, preview/status and subscription errors do not allocate run seq. Output payloads remain raw PTY bytes including partial UTF-8. State facts use explicit `live|unverifiable|exited`; only execution-side exit evidence allows exited. `status` also exposes receivedSeq/parsedSeq where available; unavailable is not zero or exited.

Runtime accepts valid focus requests in arrival order, rejects older focusSeq within connection/view scope, and assigns the next epoch. Duplicate same focusSeq/same intent returns existing/pending result within the bounded connection command state; conflicting reuse is rejected and it cannot generate a second epoch. Worker executes `{expectedEpoch,nextEpoch,holder,geometry,appearance}` in the per-run command queue, verifies binding before side effects, applies needed resize and emits ordered facts before grant. A newer accepted focus can invalidate an older pending grant at the client. Control notifications/attach/reconnect/visibility do not themselves focus. Input requires installed recovery, applied boundary at least the grant boundary and current epoch; worker rechecks immediately before PTY write.

inputSeq increases within subscription, each chunk once. Reject duplicate/stale sequence or epoch; do not replay keyboard/paste across reconnect, even if response was lost. The written result means the worker's synchronous PTY write call accepted those bytes; it does not prove shell processing. An exception after possible handoff or lost result is unknown. Large paste is separate bounded input chunks; cancellation/epoch loss may leave an explicit written prefix, never an atomic-paste claim. Already written input cannot be revoked.

ACKs are cumulative, monotonic and no greater than actually sent/parsed event boundaries. Repeated identical ACK is harmless; future/out-of-range ACK is invalid, older ACK cannot return credit twice. Runtime uses its retained sent-byte ledger, never client-reported byte totals. Charge all encoded frame bytes, including metadata/control frames. Baseline-progress similarly returns only the exact recorded transfer bytes; baseline installation remains uncommitted until final ACK N. Reserve control/error credit so a baseline larger than the window cannot deadlock.

## P-pipe and S-runtime

Runtime sends pipe hello carrying WorkerRef, pipeVersion, build diagnostics and effective bounds; worker ready echoes accepted identity/version/limits. No spawn before ready. Pipe-version mismatch rejects worker admission, never silently replaces a live worker/run. Runtime creates worker identity/incarnation, worker verifies it, both directions bound every command and result. stdout is protocol-only; stderr diagnostics must not contain credentials/VT. No second Node send/control channel.

Closed commands: `spawn {operationId,run,executable,argv,cwd,geometry,profile,appearance,budgets}`, `stop {operationId,run}`, `set-control`, `input`, `resize`, `appearance`, `subscribe/recover`, `unsubscribe`, `applied-ack`, `baseline-progress`, `status {run}`, `preview-refresh {run,knownVersion?}`. Terminal commands use the terminal schemas/bindings above; set-control is the runtime-resolved focus/blur action. Spawn records preallocated run identity before side effects; result is bound spawn confirmation or explicit non-acceptance/uncertainty. Stop result means request accepted/delivered; success requires actual exit evidence (already exited returns that evidence). No generic arbitrary method string or command execution RPC.

Pipe results echo WorkerRef/run/requestId and exact command discriminant; terminal events embed metadata once plus a single payload. Preview refresh uses `unchanged {version,status}` or bounded `preview-start/chunk/end {previewId,run,version,atSeq,geometry,generatedAtMs,vtBytes}`; snapshots contain current-screen VT only, not history, a recovery baseline or a second model. Preview version is a safe per-run version bound to the captured state; using parsed run seq is initially valid (it may cause conservative refresh after a nonvisual event). Unchanged is legal only when the worker knows the cached picture remains current. `status` returns current execution evidence, control, geometry, parsed/received positions and recovery availability (`ready|waiting-checkpoint|unavailable` plus a bounded reason). Missing/late/wrong-incarnation replies are rejected and cannot satisfy another request; pipe timeout never proves no effect. A failed link marks its routes unverifiable and fences stale deliveries without rerunning agents.

Freeze `RuntimeTerminalPort` in `./runtime`: typed `spawn`, `stop`, `setControl`, `writeInput`, `resize`, `setAppearance`, `openSubscription`, `closeSubscription`, `ackApplied`, `ackBaselineProgress`, `getStatus`, `refreshPreview`, and ordered `onEvent`/`dispose` subscription hooks. Each method takes/returns the above plain contracts; adapters return explicit accepted/rejected/unknown results, not Fastify/ws/PTY objects. `dispose` detaches the consumer; it is not run termination. W2 implements worker-side behavior against these schemas; P2 owns routing, admission, pool/connection queues and translation, not a second engine.

Runtime keeps bounded previews for **all** admitted runs, including hidden/unsubscribed ones. Poll in batches with at most one pending refresh per run; no-change reuses VT while updating checkedAt. Cache record distinguishes `generatedAtMs`, `checkedAtMs`, `stale`, latest status and last successful version; monotonic scheduling uses host clocks internally, wall timestamps are diagnostics. Refresh failure retains last preview and marks stale/unverifiable. list/get only read caches, never serialize every terminal synchronously. Controller consumes a preview only for display, never as resumable state.

## Bootstrap, admission, RPC and receipts

Only explicit `m0-local` launches on numeric loopback (127.0.0.1 or ::1), private port/temp directory. M0 serverId may be fixture-supplied; relayInstanceId and >=256-bit harness secret are fresh per launch. P2 generates secret and writes owner-only rendezvous containing bootstrapVersion/serverId/relayInstanceId/endpoint/secret; directory 0700/file 0600 on M0 macOS/Linux, reject symlink/unowned insecure paths. H1 reads/injects explicitly into CLI/view memory and cleans only its own instance artifacts. No URL/query/subprotocol/log/trace credentials, cookies, remote listeners or host-wide discovery service. These safeguards do not claim same-user process isolation or production pairing.

Freeze paths `POST /bootstrap`, `POST /rpc`, `GET /terminal` (WS upgrade). Bootstrap v1 has a small independent JSON envelope `{type:'cove-bootstrap',bootstrapVersion:1,expectedServerId?,expectedRelayInstanceId?,protocolVersion,buildVersion,capabilities,profiles,encodings}`; authenticated success returns actual server/instance/build/protocol, accepted capability intersection, profile/encoding, effective budgets and (WS only) ConnectionRef. Stable failure has kind/message/supportedVersions and no terminal/path inventory. External protocolVersion starts at 1; compatibility requires equality, independent of build. Both sides require baseline capabilities/profile, unknown optional capabilities are ignored; unnegotiated behavior is never sent.

HTTP uses `Authorization: Bearer <secret>`, `Cove-Protocol`, `Cove-Server-Id`, `Cove-Instance-Id`; bootstrap does not require business headers. RPC responses echo `Cove-Protocol`, `Cove-Server-Id`, `Cove-Instance-Id` without changing JSON-RPC envelope. Validate HTTP authority/Host against the exact bound numeric endpoint; reject DNS/rebinding names and mismatched ports. Browser HTTP requires an exact allowlisted harness Origin. For the shared terminal WebSocket endpoint, validate every present Origin against that allowlist, rejecting `null`, malformed and ambiguous values without a client-type exception. Origin may be absent for native CLI use, but absence neither proves native identity nor authenticates the connection; a [browser WebSocket handshake supplies Origin](https://www.rfc-editor.org/rfc/rfc6455#section-4.1). Every WS peer must complete the same bounded secret-bearing first message and protocol/instance negotiation before business traffic. User-Agent or a client-supplied browser/native label is not trusted identity. OPTIONS has no business dispatch, exact allowlist/method/header policy, no wildcard CORS.

Browser WS cannot set Authorization: validate Host/Origin before upgrade, then require **one text bootstrap** containing the same envelope plus secret within 5 seconds/8 KiB. No business binary frames before authenticated server response; native CLI uses the same WS first-message rule. After negotiation all terminal messages are bounded binary frames; text/second-bootstrap is a protocol error. HTTP body/headers and WS auth must validate expected instance before side effects. Limit unauthenticated sockets and never publish client-provided generation as authority.

HTTP binding: admission errors use stable bootstrap errors with 400 malformed bootstrap/headers, 401 unauthenticated, 403 forbidden Host/Origin, 409 identity/protocol mismatch, 413 body cap, 429 admission limit, 503 unavailable. Once admitted to RPC, HTTP 200 carries standard JSON-RPC result/error, including parse/invalid-request errors; notification-only traffic returns 204. Valid notification items have no response even when method execution fails. Empty batch is invalid request; invalid batch members receive id:null, valid notifications are omitted, mixed responses may arrive unordered. IDs preserve allowed string/finite-number/null types; Cove sends nonempty string IDs. Standard -32700/-32600/-32601/-32602/-32603 errors, result/error exclusive. Bound batch to 16, named-object params, no unbounded recursive data.

| Method            | Params / result; CLI route                                                                                                                                                                                                            |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `server.status`   | empty params; server/instance/build/protocol/profile/effective limits, worker/run counts and admission/health; `status`.                                                                                                              |
| `terminal.list`   | bounded limit<=128 and optional runId cursor; records for current instance with RunRef/status/control/geometry/preview metadata; `terminal list`. Pagination cursor is best-effort run-ID ordering, not a transactional snapshot.     |
| `terminal.get`    | run; one record plus bounded cached preview VT encoded only as separately fetched terminal preview transfer, not an unbounded RPC string; `terminal get`.                                                                             |
| `terminal.create` | operationId, expectedRelayInstanceId, executable, argv, cwd, geometry; operation record with preallocated RunRef; `terminal create`. Explicit executable/argv/cwd, no implicit shell string, repo registration or env-secret payload. |
| `terminal.stop`   | operationId, expectedRelayInstanceId, run; operation record with exit evidence when complete; `terminal stop`.                                                                                                                        |
| `operation.get`   | operationId, expectedRelayInstanceId; instance operation record or OPERATION_NOT_FOUND; `operation get/wait`. Waiting is bounded client polling, no seventh wait RPC.                                                                 |

The method spec table exports each params/result schema, read/write class, required capability and local-principal permission; no handlers. CLI attach uses the same terminal WS commands, including explicit focus/input/resize/recover/detach. Launch flags and effective budgets are exposed by status/help, no dynamic settings product.

`OperationRecord={operationId,method,revision,state,run?,result?,error?}`; states `accepted|running|succeeded|failed|requires_attention`. create/stop writes always return `{operation:...}`; result success is not operation success. Scope IDs to server+instance+authenticated local principal. Canonical intent is method plus validated known params (excluding operationId/network id/connection), includes expected instance/run, stable explicit geometry and argv order; recursively sort object keys, preserve array order, reject undefined/nonfinite values. Unknown optional fields are stripped before fingerprinting; no implicit path normalization/default based on current environment. Store bounded canonical text or an internal hash, never echo it or executable/cwd in diagnostics.

Reserve a receipt slot and unique ID before dispatch; same ID/same intent returns existing record even when capacity is reached; different intent returns OPERATION_ID_CONFLICT. Keep every accepted ID/canonical intent and bounded result through the instance lifetime; no eviction/TTL that permits reexecution. Full map rejects new writes as BUSY with `acceptance:'not-accepted'`. Lost HTTP/pipe response preserves accepted/unknown state; query original ID, never generate a new one automatically.
