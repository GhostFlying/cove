## Shared query vocabulary and independent fixtures

Coordinator-approved vocabulary is `caseId`, `setupBytes`, `queryBytes`, `expectedLiveReplies` (ordered byte arrays), `continuationBytes`, with explicit dimensions/modes/theme. Author bytes as hex or `Uint8Array`; keep fixture files separate on the two branches. Shared case IDs are `dsr-status`, `cpr`, `dec-cpr`, `da-primary`, `da-secondary`, `mode-report`, `color-fg`, `color-bg`, `color-palette`. `window-report` is supplemental. Observation fields such as phase (`live`, `baseline`, `replay`, `continued`), origin (`authoritative-model`, `client-parser`, `user`), `byteCut` and `occurrenceId` stay local evidence, not new protocol fields. P1a `seq` is an event identifier, never a byte offset.

At 40×10 with origin mode off and cursor moved to row 3/column 4, pinned source gives useful independent reply oracles: `CSI 5n → CSI 0n`, `CSI 6n → CSI 3;4R`, `CSI ?6n → CSI ?3;4R`, `CSI c → CSI ?1;2c`, `CSI >c → CSI >0;276;0c`. Set/reset bracketed paste then query `CSI ?2004$p`, with exact set/reset reports. Explicit foreground/background/palette RGB values make OSC reply bytes deterministic; include BEL and ST terminators and mixed set/query/reset operations. Expected replies come from pinned source plus authored context and must not be populated from the candidate adapter's observed output. Unknown properties get no invented reply.

Mandatory family coverage is DSR/CPR, DA, mode reports and colors. Also inventory and test reachable DCS status-string/window query emissions so an unlisted default reply cannot escape. Optional extension findings do not silently expand the promised production profile; failure in a required family cannot be renamed unsupported to pass. T1 owns server reply expectations and color-property supplementation feasibility. Q1's unadapted reference page must emit expected browser replies as a positive control; the adapted page must emit none automatically. Browser output is not evidence that headless natively answers the same color query.

## Concrete experiment and observables

Extend the existing Vite fixture and compiled Node/Playwright harness, keeping B0's default environment route intact. Add a `query-input` fixture mode, a browser module `probes/browser/query-input.ts`, a probe-local adapter module, a compiled `probes/node/query-input.ts` runner and `probes/query-input.test.mjs`. Small domain-named modules may split runner/adapter responsibilities. Reuse B0 managed-browser/version checks, numeric-loopback built-asset serving, deadline/error capture and cleanup by extracting only the needed lifecycle seam within `probes/`; do not create another downloader, test framework or server/client product.

The Node runner imports `@cove/protocol/provisional/terminal` through compiled exports. It encodes/decodes/validates synthetic `output` and `baseline-chunk` bytes before browser delivery and encodes/validates actual browser input bytes at the outbound sink. Grid, phase and origin annotations remain fixture-local. Reject malformed metadata/wrong run and incomplete baseline assembly before feeding xterm. Use a maximum 64 KiB baseline assembled from small chunks; this is an experimental delivery envelope, not a final recovery controller. No source aliases or engine/native dependencies in the browser package.

Use one adapted terminal and one unadapted control, sequentially where possible, with fixed geometry, font and theme. Record bounded ordered observations: action/occurrence ID, phase/generation, hook hits, actual `onData`/`onBinary` bytes, accepted outbound bytes, write callbacks and public buffer/mode state. The oracle is the authored action schedule and expected byte stream, not regex separation of a mixed sink. In no-input query cases the entire outbound stream must be empty; in input cases it must equal the complete expected user stream, including bytes identical to replies.

Deterministic overlap uses a test-only private OSC marker handled by the public `registerOscHandler` promise API: enqueue prefix + marker + query suffix, observe marker entry, then drive browser input while that write callback is still pending. Release the marker and await real write completion. Repeat with a query before the marker and a query after it, multiple queued writes, replay followed immediately by live output, and a fresh terminal's baseline followed by continuation. This proves real asynchronous parser/input coexistence without timing sleeps or mocked core events. Also run ordinary unpaused writes as a control. The marker is fixture-only, never application VT/profile or production adapter behavior.

## Bounds, registration and atomic implementation

Keep each run to one managed browser, at most two terminals/pages, finite fixture lists and one held barrier per terminal. Initial limits: 64 KiB fixture/output retention per case, 4,096 observations and 256 KiB result bytes; exceeding a limit is an explicit test failure, not silent truncation. Partition the corpus into bounded tests compatible with the existing 45-second project timeout; retain B0's work/cleanup deadline separation, reserving at least seven seconds for cleanup. Avoid an unbounded all-cases browser session. Deadlines detect failure, not correctness or throughput.

Always release held promises and dispose handlers/terminals in `finally`, then close the owned browser/listener using B0's bounded close/kill fallback and verify observed process exit/listener closure. Preserve both primary and cleanup errors. Failure injection must confirm cleanup after browser startup and after barrier entry.
