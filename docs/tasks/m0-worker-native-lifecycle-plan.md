## Source observations and recommendation

Registry node-pty1.1.0 `src/unixTerminal.ts:105–112` gives tty.ReadStream and CustomWriteStream the same fd; :115–163 handles read error/close; :236–246 destroys the read stream. `src/unix/pty.cc:354–459` spawns, sets nonblocking, publishes the master and installs the exit watcher; `src/native.d.ts` has only fd/pid/pty. N0's held-callback guard cannot protect an integer fd already queued to libuv. Its current `_fd=-1` also loses the number needed for a future owned close, so it cannot simply be reused as the new ownership state.
Recommend a **distinct close-on-exec writer fd, exclusively owned by the bounded writer until its last issued write has completed**. It refers to the same PTY/open-file description; it is not a second PTY, backend or transport. ReadStream may close its own fd without allowing an in-flight writer syscall to hit a reused number. Keep bounded admission, FIFO, settlements and paced scheduling from the seed subject to review; do not accept the seed without this native fix.

## Native acquisition and fail-closed binding

1. Add an optional bounded-writer flag to the internal Unix fork call, keeping legacy11-argument behavior and accepting a validated12th boolean only on the new addon. Duplicate only for an enabled bounded PTY; `UnixTerminal.open()` and unenabled legacy spawns must not allocate orphan writer fds. `IUnixProcess.writeFd` is optional for legacy and required/validated for bounded mode.
2. Export a narrowly named native capability/version marker from the rebuilt addon, and check it **before spawn** when bounded mode is requested. A stale prebuild must fail closed before creating a child; never silently fall back to the shared fd. JS result validation still checks distinct nonnegative integer fds.
3. On Darwin/Linux parent path after the master is valid/nonblocking, acquire writer fd with atomic close-on-exec duplication (`F_DUPFD_CLOEXEC`, minimum3). Verify the supported SDK/kernel paths during implementation. Prefer explicit unsupported failure to a blind dup+fcntl fallback: that pair opens a concurrent exec inheritance window. No Windows or other-OS support claim is added.
4. Preserve shared O_NONBLOCK state; CLOEXEC is per descriptor. Do not toggle master file-status flags after read/write setup. Added C++ follows Google C++ style without reformatting upstream.
5. **Exact transfer:** successful synchronous `PtyFork` return irrevocably transfers both fd close obligations and child-control responsibility to the JS constructor guard. Native descriptor RAII ends there and cannot cover later JS adoption exceptions. The installed native exit watcher remains the sole reaper across this transfer. Construct/validate all result fields before installing the watcher where possible; make watcher installation transactional with an explicit local ownership handoff, then no further fallible result construction. No native descriptor acknowledgment/adopt protocol.
6. Before stream/writer construction JS owns both raw descriptors. Each adoption must define its commit point: before it, guard closes the raw fd; after it, only that owner closes. Put fallible validation before adoption and inspect pinned tty.ReadStream construction failure behavior; never assume a thrown constructor means it did not take fd ownership. If that constructor can adopt then throw, the narrow factory must detect/return the actual owner for cleanup rather than blindly closing the integer again. Writer construction similarly has an explicit no-throw ownership commit after its fallible initialization. Reentrancy is fenced before external callbacks.
7. Child rollback is local to this fork/exit path. JS adoption failure requests stopping only its just-created child, destroys/retires adopted owners and closes unadopted fds, while the watcher alone reaps. Native watcher completion can precede JS callback delivery, so a JS boolean plus naked process.kill(pid) is insufficient proof against PID reuse. Keep a small native child-lifecycle state associated with the existing watcher; route constructor-rollback stop through that state, rejecting/no-op after reaping. A narrowly internal stop closure/token returned with the fork result is allowed if needed; it does not acknowledge descriptor adoption or become public raw-pid/fd API. Its stop-vs-reap boundary must serialize identity validation and signal before waitpid releases the pid. Never hold that lock across blocking waitpid (which would prevent stopping a live child); use the existing watcher structure with a bounded/nonblocking wait step where needed. No second reaper, external process manager or generic descendant tracking.

| Failure/transfer phase                   | Sole fd close owner                                                                          | Sole child stop authority / sole reaper                                                                                                                                                                                   |
| ---------------------------------------- | -------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Before child creation                    | Native guard for any acquired fds                                                            | No child, no signal/wait                                                                                                                                                                                                  |
| Child created, watcher not installed     | Native guards close master/duplicate once                                                    | Native rollback stops still-owned unreaped child / native rollback waitpid; installing watcher transfers reaping exactly once                                                                                             |
| Watcher installed, return not completed  | Native guards until successful return                                                        | Native rollback requests watcher-owned stop / watcher only; any reachable publication failure retains this route. Prefer all fallible publication before install, prove final handoff cannot throw rather than assume it. |
| Return succeeded, read adoption fails    | JS guard closes raw fds only if not adopted; partial owner must clean its own fd             | JS requests stop through returned owned-child state / watcher only                                                                                                                                                        |
| Read adopted, writer adoption fails      | ReadStream closes reader; JS guard closes still-raw writer or retires committed writer owner | Same JS stop request / watcher only                                                                                                                                                                                       |
| Both adopted, later setup fails          | Stream + writer each close their fd once                                                     | Same JS stop request / watcher only                                                                                                                                                                                       |
| Child already reaped during any rollback | Current fd owners still clean normally                                                       | Recorded reaped state rejects signal; no repeated waitpid                                                                                                                                                                 |

A constructor failure must leave no owned live leader or unaccounted descriptor after bounded fixture cleanup. Preserve process-group uncertainty: stopping/reaping the leader is not proof arbitrary helpers exited; a fixture-owned helper has its own identity/check/cleanup. Fault injection stays package-local. Ordinary legacy kill semantics are not expanded by this rollback contract.

## Writer lifecycle and truthful settlements

Maintain separate `accepting/state` and owned `writeFd`; retirement is not represented by losing the only fd number. Maintain at most one issued fs.write per writer, and a close-pending flag. No new writer creates/borrows another fd after retirement.

| Trigger                                             | Required action                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| --------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Active drain                                        | Issue one bounded write on owned writeFd; retain full Buffer allocation and task slot through callback/settlement; no synchronous admission result claims delivery.                                                                                                                                                                                                                                                                                                                                  |
| Dispose/read error/read close/natural-exit callback | Atomically stop admission and future drain/timers, mark close pending. With no issued write, close writer fd now; otherwise retain it and its in-flight buffer until that callback returns. Repeated triggers are idempotent.                                                                                                                                                                                                                                                                        |
| In-flight callback after retirement                 | Account actual returned prefix/error, issue no further write/retry, close owned fd once before calling external settlement callbacks. Settle active and cancelled queued tickets once; do not report queued unwritten bytes as delivered.                                                                                                                                                                                                                                                            |
| Synchronous fs.write submission throw               | Wrap the call. If it throws before request handoff, clear issued state immediately (no callback will arrive), fence admission, add zero delivered bytes for this attempt, fix the active prefix/error and cancelled queued outcomes exactly once, close the owned fd once, then perform their synchronous settlements and publish owner completion in the common order below. Preserve bytes from earlier completed partial writes. Cleanup/settlement callback throws cannot skip owner completion. |
| Permanent write error                               | Fence writer, cancel later queued work, close after this request completes, report prefix/error once. Keep native-process liveness separate.                                                                                                                                                                                                                                                                                                                                                         |
| kill(signal)                                        | Preserve process signaling semantics; it is not immediate exit proof. Exit/read close causes retirement. Explicit writer disposal remains possible without claiming process death.                                                                                                                                                                                                                                                                                                                   |
| JS callback throws/reenters dispose                 | Owner state/close decision is already fixed; finally releases callback/task accounting. Error cannot skip close or re-admit work. No repeated callback queue.                                                                                                                                                                                                                                                                                                                                        |

Submission seam contract matches Node: either throw before handoff or hand off exactly one callback, never callback-then-throw. Keep per-request settled state so reentrant disposal/duplicate injected callback cannot create a second settlement/close; a seam contract violation fails the test, not a fabricated second completion. A submit throw during active draining and during disposal reentry must both terminate without a stuck in-flight flag.

Use one owner-controlled close operation after no issued write remains (synchronous close is the minimal ordering surface; no concurrently queued fs.close). Mark ownership surrendered before calling close so callback reentry cannot close again. Treat close errors explicitly; never blindly retry an integer fd after EINTR/ambiguous close where it may already be reused. Document supported Darwin/Linux behavior and conservatively report resource-close uncertainty rather than success or a retry that can close another resource. Controlled negative tests model such ambiguity; no unsafe host experiment is required.
An already-issued write may still reach the **original PTY** after disposal; cancellation cannot recall it. Record actual prefix and uncertainty, never promise “dispose prevents all delivered bytes.” The duplicate can postpone final PTY-master hangup until its pending callback returns. Explicit destroy's existing SIGHUP path must still function; natural exit must not wait for master hangup before retiring writer. A libuv stall may postpone settlement/close: bound resources and report pending, not force-close the fd to meet a timer.
N1 exposes one finite owner-completion contract, selected here as a readonly completion promise on each enabled bounded writer/PTY: it settles once with `{ kind: "closed" }` after confirmed descriptor close AND completion of owned synchronous ticket settlements/accounting, or `{ kind: "close-uncertain", error }` after an ambiguous/failed close attempt AND the same settlement/accounting boundary. It is created before any retirement can happen and never rejects; uncertain outcome is explicit data, not success. One record per owner, no polling/event replay/history or public raw fd. Legacy/unenabled paths do not manufacture a duplicate-owner promise. Public declarations, src and generated lib agree; exact member spelling is implementation detail.
Retirement with an issued write leaves the promise pending; idle retirement, permanent callback error and synchronous submit throw all reach the same closeout. Exact order: (1) fence admission and fix ticket outcomes; (2) after no native write remains issued, surrender/close the fd once and fix its immutable close result; (3) invoke each still-owned synchronous ticket settlement once, releasing its Buffer/task/callback accounting in finally; (4) only when all such owned settlements have returned/thrown and their accounting is released, fulfill the owner promise once with the fixed result. A throwing callback must not skip other settlements or final completion; retain the existing error-reporting behavior without an unbounded deferred error queue. Repeated dispose/reentry cannot reopen the writer, close twice or publish completion early.
“Owned settlements” means the package's finite synchronous invocation of callbacks for accepted tickets, including a callback already on the stack when it reenters dispose. Keep the existing callback/task count charged until that invocation unwinds; closeout checks that count, not just an empty input queue. It does not await arbitrary returned promises, client async work, microtasks or client-retained Buffers; those are outside this API's ownership and completion guarantee. Do not introduce an async callback scheduler or extra task queue. At retirement admission is fenced and the retained set is bounded by existing256-task/64KiB limits; a client callback that never returns can block JS progress, so keep ownership charged rather than claim a wall-clock completion bound or attempt forced release. Idle/no-ticket retirement completes immediately after the close result is fixed. Promise observers execute after this boundary and do not extend or reopen it.
N1's tests use a finite external owner ledger: charge one slot before admission; hold it through the native write completion and all package-owned synchronous settlement invocations/accounting defined above; release it exactly once only on the resulting `closed` completion. Physical fd closure alone does not release this ledger slot. On `close-uncertain`, keep that slot as a bounded tombstone/fatal-resource condition, deny admission when the configured cap is reached and report the uncertainty. Do not retry the surrendered fd or free capacity merely because the object retired, the child exited or no write ticket exists. N2 will wire this already-defined contract into its run/aggregate accounting; N1 implements/tests the package surface and a fixture ledger only, without production adapter code.
Count this retired-but-not-closed writer as a resource still owned. Each enabled PTY has exactly one additional fd; run/admission slots or an equally bounded retired-owner account remain occupied until the owner-completion boundary above, including owned synchronous settlements/accounting; descriptor closure may occur earlier. Otherwise repeated spawn/dispose could defeat a nominal maxRuns cap. Retain existing64KiB/256-task maxima and worker aggregate budget; no hidden deferred-close list or unbounded settlement queue. N2 must consume pending-close accounting later, but N1 tests/proves the native resource surface now and does not implement N2 adapter/pump.
