## 3. Proposed concrete API

Use protocol types only through built package exports. The following is an implementation proposal consistent with P1b, not a new wire contract:

```ts
createTerminalModel({ run, geometry, appearance, effectiveBudgets, onAutomaticOutput })
  -> TerminalModel

TerminalModel.apply(event: RunEvent, payload?: Uint8Array): Promise<EngineState>
TerminalModel.continueUnpublishedOutput(bytes: Uint8Array): Promise<EngineState>
TerminalModel.barrier(): Promise<EngineState>
TerminalModel.captureBaseline(): Promise<EngineBaselineResult>
TerminalModel.capturePreview(): Promise<EnginePreviewResult>
TerminalModel.dispose(): void
```

`apply` accepts already-authorized worker facts, not untrusted client requests: output bytes, actual resize, control-presence change, appearance change, or exit boundary. The worker remains the only seq allocator and epoch arbiter. T2 validates run binding, finite contiguous event sequence and event/payload shape before admission; it does not independently grant control, emit a run event, allocate an epoch or execute input. A control event's geometry must agree with the model after any preceding resize; it is not an implicit second resize. Exit is a boundary supplied by the worker, not engine-derived process liveness, and retains the model for final display until disposal.

`continueUnpublishedOutput` is the narrow execution-continuity path required by P1b's run-seq exhaustion rule. W1 invokes it only after fencing stream/control delivery; it latches delivery-fenced state, continues bounded raw-byte parsing and live query replies, and never invents another seq, wraps the counter or labels the PTY exited. Subsequent normal event admission and ready baseline/preview delivery are refused. It adds no protocol event; W1 still owns the fence and explicit stop. Its automatic-output record has no published `atSeq` (`null`), so callers cannot mistake it for a client-applicable boundary.

Suggested plain result shapes:

- `EngineState`: admitted/received and completed/parsed seq, geometry, effective appearance, supported query IDs/known palette indices, active-buffer identity, focus-report mode, recovery `{state:'ready'|'waiting-checkpoint'|'unavailable', reason?}`, and byte/count utilization required to enforce the local bounds. No process liveness claim.
- `EngineBaselineResult`: either a ready detached value `{profile,encoding,checkpointSeq,atSeq,captureGeometry,currentGeometry,coverage,vt,tail,appearance}`, or bounded waiting/unavailable reason. It has no subscription/baseline ID or chunk count: W2 fixes the subscription boundary and transfer envelope. `appearance` is local capture metadata; do not add it to the frozen wire descriptor by inference.
- `EnginePreviewResult`: either detached `{atSeq,geometry,vt}` for the active current screen or a bounded failure. Worker stamps run/version/time and decides unchanged; runtime owns the cache. This is never a recovery baseline.
- `onAutomaticOutput({atSeq:number|null,kind:'query'|'focus',bytes})`: one synchronous caller-provided sink invoked in operation order, once per actual reply/report. W1 owns the bounded PTY input route. No internal retry, second transport route, subscriber callback or hidden reply accumulation. Exceptions from the sink are caught and surfaced as a bounded adapter failure, never allowed to disappear inside the xterm parser callback or silently retried.

The implementer may adjust method/type names and internal module split without user review, provided these ownership and semantic boundaries remain intact and the final signatures are recorded for W1. Use a small local error/result union for invalid admission, capacity, disposed/faulted model and recovery failure. W1 maps those to the frozen public error taxonomy; do not allocate protocol codes locally. Recovery unavailability alone does not fault or stop the live model.

### Admission, completion and disposal

All mutations and captures use one FIFO. Accepted event sequence order is independent of byte offset; keep both only if needed, never label bytes as seq. A write result and `barrier` resolve only after xterm's callback, then commit `parsedSeq`. A barrier captures all work admitted before it, not future calls. Snapshot generation executes between operations against that exact completed state; later events cannot enter the snapshot. Concurrent call tests must prove this, including callback-delayed writes.

Validate dimensions 2–120 × 2–40 and any lower effective geometry bounds, effective budgets, known appearance and payload bounds before allocation/state change. Output payloads remain original bytes, including invalid or incomplete UTF-8; never per-chunk decode/re-encode. Copy admitted input bytes so caller mutation cannot change future parsing. Only output carries a payload, up to 64 KiB per accepted event; W1 splits larger native reads into ordered output events. Reject before admission when local queued bytes including the in-flight write exceed `parseHardBytes` or pending operation count exceeds the effective command bound. Rejection does not advance seq or mutate state. Expose pending bytes for W1's `parseHighBytes`/`parseLowBytes` flow control; T2 never pauses a PTY itself. Bound zero-byte barriers/capture requests by count too.

Same-size resize is an actual no-op on xterm; genuine resize occurs after prior writes and before following output. The worker avoids publishing needless resize facts. The engine neither fakes a resize to repair recovery nor delays the actual authoritative resize until a VT sequence closes.

Disposal is idempotent, immediately closes admission and automatic-output emission, invalidates late callbacks, detaches parser/listener registrations, disposes the one engine/addon if used, releases owned queues/checkpoint/tail buffers, and settles every pending promise with a defined disposed result. Do not depend on xterm calling a pending write callback after disposal. Calls after disposal fail explicitly; they must not hang, answer a query or affect a successor model. There are no polling timers or child processes in T2.

## 4. Checkpoint, tail, preview and query invariants

### Recovery

Reuse the proved algorithm in `probes/logical-grid-recovery.ts`, the required `sgr`/`savedState` VT construction from `probes/recovery-checkpoint.ts`, and its bounded tail, with the approved read-only private surface from `probes/xterm-recovery-state.ts`. Do not promote `source-derived-recovery.ts`, strict geometry installation or synthetic witness hints. Keep the old probes operational as independent historical regressions.

Run pinned module/version conformance once per adapter construction or cache the immutable successful module check locally; do not hash package files on every cell read. Continue validating the actual private surface shape at use. Do not expand private access beyond the already approved parser/UTF-8/current/saved-register/charset/buffer reads. A version/shape mismatch fails explicitly; no fallback to arbitrary screen text, silent mode deletion or package patch. No private value is ever installed in another engine or sent on wire.

Start with a valid empty checkpoint at seq 0. A candidate checkpoint is generated only after a completed operation with parser in ground and no UTF-8 interim bytes. Printable preceding-join state is handled by T1's proved logical-grid final-print construction; it is not automatically unsupported. Candidate construction is pure: no writes, resize, query emission or source mutation. Commit the complete candidate and reset the tail only after its byte/coverage checks succeed. Keep the previous valid checkpoint/tail when safe if replacement fails; do not return a half-built baseline.

Tail is the exact original output since checkpoint C through completed boundary N; C0 effects are already represented either in the checkpoint or once in the tail. Never serialize the post-tail screen and append those same bytes. A write callback alone is not parser ground. After ordinary parsed output, refresh at a bounded byte threshold (proposed half the effective tail budget) and on capture when ground, so sustained printable output does not become permanently unavailable. Avoid serializing full history after every tiny output event. If the current tail exceeds its cap while no checkpoint is possible, retain no unbounded raw log, report unavailable, and continue live parsing; a subsequent proved checkpoint restores availability. Tail loss is never disguised as empty successful recovery.

Actual geometry changes invalidate an earlier checkpoint for this encoding, even if bytes since C appear harmless. After resize during split UTF-8/CSI/OSC/DCS, report `waiting-checkpoint` until parsing reaches a valid boundary at the new geometry, then capture a fresh same-geometry checkpoint. Do not stall output behind a waiting capture; capture returns availability and W2 owns bounded retry/deadline. A sequence that remains open may expire, but ordinary finite fixtures must recover after their suffix. Appearance updates not represented in raw output likewise require a checkpoint reflecting the update before returning a ready baseline; they must not make an old tail undo a newer appearance fact.

Snapshots preserve required normal and alternate current content and configured retained normal history. Default history is 1000, with forced 3-line tests. Coverage states actual retained/included history; `trimmedBefore` must truthfully reflect omitted/evicted history (a conservative true is allowed when exact eviction cannot be established cheaply). Never drop hidden normal or required alternate data to fit. Set `resizeContext:'requires-baseline'` conservatively when complete retained reflow context is not proved; the accepted practical topology limitations mean T2 need not claim `complete` for every checkpoint. This flag triggers recovery after a real resize, not same-grid fake resize.

VT cap ≤8 MiB; raw tail ≤64 KiB, or effective lower caps. Enforce finite limits before allocation and before each append. Account peak retained checkpoint, candidate, returned copy, tail and queue storage, including a bounded replacement overlap; do not call encoded payload accounting a measured RSS bound. Normal/alternate model geometry/history are finite; resource reports must distinguish those bounds from xterm's internal string/parser storage and process RSS, which the later worker/resource gates measure. No unbounded second model or restoration self-test in production. Detached result buffers cannot mutate the live engine or its cached checkpoint. W2 owns returned snapshot lifetime and aggregate accounting.

The local checkpoint VT must include the known effective appearance required for cell colors and restored query behavior, using ordinary bounded OSC SET sequences, never query sequences. Keep checkpoint-time appearance consistent with subsequent raw tail setters; a later explicit appearance replacement invalidates/rebuilds as above. Unknown values remain unknown. This uses the accepted VT+metadata format and Q1's setter-preserving client path, without a new wire field.

### Preview

Generate current active viewport VT directly from the settled model with a bounded screen-only emitter or a verified public serializer viewport option. Reuse the cell/SGR encoding primitive; never serialize all history and then slice bytes, and never instantiate a second model. No normal history prefix, raw parser tail or pending query enters preview. Keep style and complete VT/UTF-8 sequence boundaries; exceeding `previewBytesPerRun` (≤64 KiB) returns a bounded failure, not truncated escape data. Incomplete live parser state does not by itself prevent a display-only preview of settled cells. Capture changes no model, controller presence, query count or recovery tail. Runtime can retain a stale older preview after failure; T2 adds no cache-refresh timer.

### Authoritative replies, appearance and focus reports

Consume `QUERY_SUPPORT`, default appearance and frozen Q1/T1 query fixtures. The nine advertised families remain DSR status, CPR, DEC CPR, primary/secondary DA, tested private-mode report, foreground, background and known palette-index queries. Match exact fixture bytes; do not advertise Q1-only cursor-color, DCS status/margins or window reports as T2 additions. Stock engine emissions outside the advertised intersection are not evidence of negotiated support and must not enlarge capability lists.

Model-owned query state comes from live parsing. Appearance-owned query state is bounded: known foreground/background plus up to 256 unique palette indices. Ordered explicit appearance replacement and live OSC 4/10/11 set/query behavior use the same effective state. Preserve mixed setter+query order (including Q1's `OSC 4;1;#aabbcc;1;?` case), BEL/ST termination, valid color normalization and applicable color resets; unknown values get no invented reply. Reuse pinned xterm semantics and Q1 expectations, not an ad-hoc regex classifying onData strings. All replies go through the one live sink; generation, preview and external receiver replay never call it. Production exposes no restore/replay-into-authority API.

Control is already resolved by W1/P2. When mode 1004 is enabled, effective presence false→true emits `ESC[I`, true→false emits `ESC[O`, holder A→B emits neither; disabled mode emits neither. Track presence even while disabled, so later transitions are interpreted correctly. Observer focus/connection/visibility is absent from the engine API. Mode toggles themselves are not synthetic focus transitions. These are classified as focus reports, not queries. Query/report behavior remains active with zero clients because the engine has no subscriber dependency. A fresh replacement model cannot inherit old listeners or appearance overrides.
