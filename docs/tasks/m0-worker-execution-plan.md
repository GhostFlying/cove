## Deliverable and milestone boundary

Deliver a compiled worker subprocess that owns each assigned PTY and exactly one T2 model, handles supported commands over one framed stdin/stdout pipe, applies output/control/resize/appearance/exit in one per-run order, and replies to terminal queries through the authoritative model even with no observer. Logs use bounded stderr only. Do not use `process.send`, Node IPC messages, a second event socket, worker_threads, or a runtime-side model.

W1's real production execution core has a parsed-event consumer hook. W2 will consume this hook to implement delivery; independent W1 tests consume the same compiled public hook to verify raw output and ordering. It is not a hidden test mode. W1 does not broadcast unlimited live output over the pipe without subscriptions, fabricate an attachment baseline, or treat preview VT as a baseline. The W1 pipe endpoint handles spawn, stop, set-control, input, resize, appearance and status. Valid subscribe/recover/unsubscribe/applied-ack/baseline-progress/preview-refresh requests return correlated `CAPABILITY_UNAVAILABLE` until W2 supplies their handler. Malformed or foreign requests are rejected at their earlier validation boundary.

This is a milestone implementation subset, not a claim that W1 alone implements the complete `RuntimeTerminalPort`. Frozen hello/ready has no capability field; do not add one. Its ready response establishes matching pipe version, worker identity and effective budgets, not an invented full feature negotiation. ## Ordered execution and control semantics

A run has one pump and one bounded pending byte/command account. PTY callbacks reserve/copy bounded raw byte blocks before enqueueing; an oversize callback is split into at most 64-KiB output facts without a UTF-8 string conversion. One model apply is in flight for the run. Do not also fill T2's internal queue with the same entire backlog: account the owned input block, admitted pump blocks and T2 retention distinctly. Yield between bounded batches so another run, control reply and cleanup can execute.

Assign increasing safe-integer seq at the pump's event admission point, exactly once. Output event identity contains the run and next seq; apply its same bytes to T2. Publish only on successful parse completion. Status distinguishes received from parsed; `atSeq` is the relevant completed boundary, never the number of a queued write merely received by the pipe. Native exit is queued after all earlier captured data and yields exactly one ordered exit event after parsing that data. A late callback after disposal belongs to the old session generation and cannot allocate a new event or alter a successor.

Command acceptance order is not a fabricated global order across the duplex pipe. The per-run pump orders callbacks and admitted commands; replies echo worker incarnation, run, requestId and commandType, plus operationId/inputSeq where required. Every completion is checked with protocol correlation validation in consumer tests. Duplicate outstanding requestId is rejected before executing again. Do not add a permanent worker operation ledger parallel to P2: a run is never spawned twice under the same live or retained run identity, duplicate stop is safe, and P2 supplies user-visible operation receipt/retry semantics. Retain bounded run identity/status records for the worker lifetime; reaching that cap returns BUSY and lets P2 drain/rotate the worker. Never evict a record and silently allow that run ID to execute again.

Runtime alone serializes focus requests. Worker validates `expectedEpoch` against committed state and rejects stale requests at execution time. A nonnull holder requires `nextEpoch=expectedEpoch+1`, full current connection/view/subscription identity and a representable counter. A release at a positive epoch retains the epoch and clears the holder; do not increment or resize simply because the last client blurred/disconnected. Frozen schema's nextEpoch minimum is one: there is no invented epoch-zero release command. Repeated no-op releases have no extra model focus report.

If a grant changes geometry, wait for preceding parses, resize the owned native PTY, apply/publish the ordered model resize, then optional ordered appearance, then ordered control. Geometry-changing resize advertises `requiresBaseline` according to T2's conservative recovery coverage; W1 does not make up a replay-safe reflow claim. Same-size resize/grant avoids native/model resize and preserves recovery state. Control's geometry must equal the now-applied model geometry. Only after the complete transaction settles may its accepted result expose the new epoch/boundary. Output arriving during native resize is enqueued after the transaction; SIGWINCH is not proof the child has repainted.

A native/model failure after a partial resize or control transition is not rolled back by assertion. Fence further input/control, report the existing typed failure/unknown outcome as appropriate, mark status uncertainty/recovery unavailability, and require P2 inspection. Never expose a successful grant for a partially failed transaction. Output/parser health and native process liveness are separate dimensions.

Input requires an exact current holder identity, current epoch and strictly advancing inputSeq within the full SubscriptionRef, as frozen by P1b. Losing and regaining control does not reset that subscription's counter; a replacement subscription has its own identity. Validate again at execution, so queued old-epoch input is rejected after takeover. Retain the highest admitted/attempted input sequence to prevent a duplicate execution; gaps need not fabricate missing input. Account these per-subscription records within a finite registry budget and reject new admission when full rather than evicting an identity and allowing replay; W2 can reclaim records only when its subscription lifecycle makes the old identity permanently invalid. Reserve the entire byte intent before admission; do not truncate or send a prefix because the queue filled. A pre-handoff rejection has zero native writes. Exactly one native write attempt constitutes local written acceptance with writtenBytes; it does not prove child consumption. A throw/transport loss after possible handoff yields RESULT_UNKNOWN/acceptance unknown and never schedules a retry. Repeated payloads with new sequences remain genuine user input, even when identical to terminal query replies; no escape-string regex decides provenance here.

All user and automatic bytes use the same bounded per-run PTY write path. Automatic replies are inserted at the model observation point before later pump operations; they bypass user focus authorization, not memory accounting. Query handling is independent of listener count. Switching A→B while both are focused holders changes epoch but does not manufacture focus-out/in; T2 emits reports only on null/non-null effective presence when mode 1004 is enabled. Capture/status never synthesize query bytes. An over-capacity automatic sink faults explicitly; it cannot quietly drop replies or loop retrying.

At output-seq exhaustion, stop issuing public ordered facts/control grants and report COUNTER_EXHAUSTED, retain the same process, continue bounded live parsing/query authority through T2's `continueUnpublishedOutput`, and keep explicit stop available. Do not wrap counters, change run ID or automatically restart. Epoch/input counter exhaustion likewise fences the affected writable authority and preserves inspect/stop.

## Pipe, resource accounting and lifecycle

Use the frozen CP decoder, metadata validators and semantic checks: 16-byte header, 4096-byte metadata, 65536-byte payload; consume the returned byte count, respecting 32-frame/256-KiB decode slices. Accept one hello first, compare exact WorkerRef/pipe version/effective budgets, and reject commands before ready. Validate canonical UTF-8 spawn JSON through `validateSpawnPayload`; executable/argv/cwd are explicit, with no shell-string concatenation or fallback executable. Spawn effective budgets must fit the worker-admitted budgets. Worker environment policy is deliberate and documented (inherit the execution environment with required terminal settings); do not introduce arbitrary remote environment fields into the wire.

The stdout queue has one owner. Once writable.write returns false, that frame has been handed off: retain its order, stop dequeuing until drain and never resend it. Limits include queued encoded bytes and the Node writable buffering measurement, with reserved control capacity and a cap on pending responses. Priority chooses eligible unsent work; it cannot move a reply in front of an already-enqueued frame. Intake pauses or rejects before exceeding pending command/byte caps. Malformed framing, foreign worker identity and EOF invalidate the endpoint instead of scanning for a new header or accepting a replacement incarnation on the same pipe. Pending commands receive an explicit local uncertainty classification; a broken pipe cannot promise delivery of their error frames.

Start from negotiated finite values bounded by M0 limits: maxRuns 128, geometry 2..120 by 2..40, history 1000, parse low/high/hard 128/512/1024 KiB, input queue 64 KiB, pending worker commands 256, pipe queue 4 MiB, worker accounted bytes 64 MiB and reserved control 64 KiB. Lower test budgets exercise boundaries. Budget all run models/checkpoints/tails, owned pending output, user/automatic input, pending commands/results and transport buffers before admission. T2's resource values cover its own adapter retention and are not full process RSS. Keep both accounting high-water marks and sampled RSS in evidence without falsely calling either a proof of the other.

Pause only the affected PTY at high parsed-backlog water and resume below low after actual progress; no XON/XOFF bytes, timer-based unconditional resume or dropped live data. If a final native callback cannot fit the hard/worker cap despite pause, make the failure explicit, fence the affected run and perform bounded owned cleanup rather than discard authoritative bytes and pretend continuity. A slow delivery consumer belongs to W2; it must lose its delivery eligibility, not pause unrelated PTYs. Native input's own hidden buffering must be included or bounded by the native adapter qualification below; worker queue counters alone do not establish that property.

Session states distinguish starting/live/stopping/exited/disposed and separate I/O/parser failure from process death. Only native exit evidence supports `exited`; write/resize/kill exceptions do not. `stop` is a command accepted for the owned run, not an instant exit assertion. Close admission, perform an owned graceful stop, then bounded escalation if still alive (initial test policy: 2 seconds graceful plus 1 second forced observation, configurable finite deadlines). Native exit cancels subsequent signal timers so reused PIDs are never targeted by late callbacks. Dispose listener/model resources once; preserve bounded final status for inspection.

Main handles parent stdin EOF, stdout EPIPE and local termination signals with the same bounded shutdown path. This is parent/worker loss, distinct from client disconnect: P2 must never turn a browser disconnect into worker EOF/stop. No detach/keeper or automatic child restart. Use verified ownership from native creation and the pinned adapter's documented process-group behavior; never kill by executable name, broad process scan or stale PID alone. Qualify group termination on both OSes with a child/helper fixture while its session is owned. Record which descendants were verified; root exit is not proof all descendants died. Unverifiable survivors/cleanup timeout fail acceptance and remain explicit, not silently declared reaped. SIGKILL of the worker is inherently different from graceful disposal; tests have an outer finally that cleans up only their independently recorded owned processes and reports that distinction.

Status is a bounded ordered observation from cached settled T2 state or a barrier; it does not serialize a baseline/preview or instantiate another model. Read-only status remains available for a fenced run. W2 later serializes snapshots via the run service boundary and supplies preview/version handling. P2 schedules/cache-refreshes all runs, including never-observed runs; W1 must keep their live parser/query path active now.
