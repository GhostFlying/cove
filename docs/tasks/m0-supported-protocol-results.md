## Frozen source surface

`@cove/protocol` now publishes compiled `./identity`, `./errors`, `./profile`, `./budgets`, `./terminal`, `./pipe`, `./runtime`, `./bootstrap`, `./rpc` and `./view`, preserving both provisional exports. The package remains Zod-only, with no new lockfile, pin, root configuration, PTY, server, controller or renderer implementation. Provisional lanes 1/2 retain their behavior. Frozen terminal/pipe lanes are 3/4, revision 1; both use the P1a 16-byte header and class codes 1 command, 2 result, 3 event, 4 error. Raw VT/input bytes remain payloads, not JSON metadata. `./runtime` and `./view` contain neutral interfaces only.

The public profile is `pragmatic-logical-grid-v1` with `vt-checkpoint-tail-v1` encoding. It requires current visible logical-grid state, ordinary continuation, budgeted normal and alternate buffers, ordered recovery and bounded/parser/query behavior. Saved SGR/charset and retained off-grid physical topology remain explicit diagnostics. No engine-private state is transmitted. The nine advertised query families are the frozen Q1/T1 intersection, including known palette index 1. Domain errors are fixed codes 1000–1020 with fixed public messages/actions; uncertain input uses `inspect-run` without an operation receipt, while uncertain create/stop retains `query-operation`. Standard JSON-RPC errors remain -32700 through -32603.

The six closed operator methods are `server.status`, `terminal.list`, `terminal.get`, `terminal.create`, `terminal.stop` and `operation.get`. Their method table publishes params/result schemas, read/write class, capability, local-principal permission and CLI route. Creation/stop use canonical validated intent, a preallocated run in every public receipt, same-ID replay ahead of capacity admission, and conflict rejection. The protocol defines no handlers or durable/restart ledger. The shared terminal WS endpoint checks every present Origin; absence permits only bounded unauthenticated bootstrap, and every peer needs the same secret-bearing first message. A real HTTP/WS adapter must preserve malformed/multiple raw Origin headers as rejection rather than normalizing them to absence.

M0 engineering ceilings include 128 runs, 2–120 columns and 2–40 rows, 1000 normal-history lines, 8 MiB VT plus 64 KiB tail in at most 129 chunks, 64 KiB frame payload and 4096-byte metadata, 256 KiB/32-frame decoder turns, 256 KiB subscription credit plus reserved control, 64 KiB input queue, 4 MiB pipe queue, 8 MiB aggregate preview, 16 RPC batch items and 4096 instance-lifetime receipts. Effective budgets are validated together so a full framed chunk/control message and all admitted run previews can fit. These are contract/admission bounds, not measured latency or RSS guarantees.

## Deterministic and negative evidence

`tests/fixtures/protocol/m0/manifest.json` SHA-256 is `1adad53aa2d3b892c6bcd26877693e51f65cdb1343590008e11af86e802800c7`. It pins four authored JSON fixtures for profile, terminal N/N+1 recovery, worker pipe/preview and local admission/RPC/receipt flows. `consumer-contracts.test.mjs` reads them through compiled public exports, verifies each digest, and checks literal base-v1 capability and optional-field projection fixtures with explicit refusal to send an unnegotiated extension. That is a compatibility fixture, not a real old/new runtime-build test. `package-boundaries.test.ts` promotes all emitted Cove declarations verbatim to ES-only `.ts` compilation, compiles fake `RuntimeTerminalPort` and `TerminalView` implementations, then injects `URL` to prove a host-global leak fails. The protocol-local third-party declaration skip remains limited to Zod's documented unused `URL` reference; it does not exempt Cove declarations.

Review-driven regressions cover fixed safe public errors, command/result epoch and run binding, arbitrary valid baseline chunk partitions, transfer identity, framable effective queues, fresh recovery subscriptions, checked control grants, nested worker status/input evidence, native WS Origin absence, RPC instance/method/result binding, semantic appearance, and preallocated public create receipts. The final correction validates the accepted create receipt before replay, gives uncertain input a safe no-replay action, and exercises fixture-driven focus/input/ACK ledgers and an 8-MiB baseline with recorded-byte credit return and reserved control. It also checks wrong and literal-null WS Origins, optional-field projection and unnegotiated-extension refusal. The consumer suite inventory floor rose from 9 to its 12 named tests. The initial consumer fixture manifest failed after JSON formatting changed bytes; its digests were regenerated from the final formatted fixtures. A tooling test initially expected the old inventory floor of 18 after the suite grew to 21; that assertion was corrected before the final gate. The correction's first lint run flagged conditional assertions in the new ledger, which were moved outside the conditional before the passing gate. These failures were not treated as accepted tests.

## Handoff boundary

T2 consumes the profile/checkpoint/query fixtures and still must implement and validate one authoritative engine. W1/W2 consume pipe/runtime framing and must implement the sole PTY/model/reply authority, bounded recovery, ordered ACKs and previews. P2 consumes admission/RPC/receipts and must implement the actual loopback HTTP/WS listener, secret/rendezvous permissions, atomic receipt reservation and worker pool. P3/V1 consume bootstrap, terminal frames and `TerminalView` and must implement a transport-injected controller and real browser adapter. H1/C3/X1 still owe real Codex/TraeX/Claude Code and 100-PTY qualification; F1/E1/C4b owe actual old/new runtime compatibility. None of these later gates is counted as passed by P1b schemas or fixtures.
