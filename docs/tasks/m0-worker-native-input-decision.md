Option A must state its exact private surfaces before approval. A plausible shape is a guarded replacement of the per-instance writer plus lifecycle bridge, not a process-global fs.write/console.error monkeypatch and not polling private queue length. Direct raw-fd writes are also a private integration if the fd is outside IPty: they bypass native lifecycle and must coordinate ownership, pending I/O and closure. Keeping the npm pin unchanged does not remove maintenance obligations or constitute public-API compliance. Reject this option if the proposed seam cannot observe asynchronous errors and retire all later writes reliably.

For option B, the minimal proposed contract is: atomically reject an entire byte intent before copying when the configured queue cap is insufficient; otherwise assign a local write ticket, retain accounting for all allocated buffers, settle that ticket exactly once on completed kernel writes/error/close, and expose bounded pending-byte/error state. Partial success on error is uncertain, never automatically replayed. A nonblocking automatic query sink can admit synchronously and settle asynchronously, so it cannot deadlock the model apply callback. The worker can defer its command result to a truthful settlement boundary without promising shell consumption. Exact API spelling and whether a callback or event carries settlement are implementation choices for the reviewed patch plan, not a new terminal wire revision.

If older synchronous written acknowledgements have already been emitted, a later native error must not be represented as retroactively certain delivery. The implementation plan must say which acknowledgements are delayed until settlement and how remaining in-flight commands become unknown. Preserve P1b's lower-level meaning—bytes accepted by the PTY write path, never application processing—and have the protocol owner review any semantic mismatch rather than silently redefining receipts.

Both A and B must count full retained buffer allocations, not merely `length - offset`: partially written buffers still retain their full allocation until released. Count the in-flight task once, the worker queue separately, and bound metadata/task count as well as bytes. Query/focus replies share the same writer and must retain bounded admission/progress; neither a second unaccounted priority queue nor silent dropping is acceptable. A capacity rejection must not truncate the current intent. Dispose must settle retained tasks as uncertain/cancelled according to actual handoff and invalidate scheduled callbacks. A generation check prevents subsequent writes; it does not recall an already-issued fs.write. Verify fd lifetime around in-flight writes rather than claiming a JS flag alone proves no descriptor-reuse race. If the required lifetime guarantee needs an extra native ownership mechanism, report that exact expansion before including it in either option.

## Process-group cleanup is a separate engineering boundary

Leader-only kill and swallowed errors are verified source limitations. They do not by themselves require changing node-pty: a worker-owned POSIX adapter may signal verified owned process groups using OS APIs and bounded host process evidence, retain signal errors, cancel late escalation after verified death, and check remaining owned helpers. This can stay inside accepted W1 process lifecycle scope if it is proved on macOS and Linux and does not acquire unrelated processes. It must distinguish process identity from a bare recycled PID and must not signal the worker's own group.

The author's owned-child/helper harness must establish actual PID/PGID/session/TTY behavior, what survives leader-only stop, graceful/escalated results and final cleanup. It should report helpers that escape the original group rather than claiming arbitrary daemonized descendants are covered. No broad kill-by-name, keeper, automatic respawn or host-wide process manager is proposed. A need for a new native lifecycle primitive or a reduced cleanup guarantee would be escalated; routine verified OS signaling is not automatically a dependency-patch decision. Worker SIGKILL cannot be made equivalent to successful graceful cleanup by a wrapper, and the external test finally must distinguish its recovery work from worker-owned cleanup.

## Finite evidence needed before the final recommendation

1. **Raw byte execution:** exact compiled worker/native artifact and OS/ABI; `encoding:null` yields Buffer; NUL/high bytes, split UTF-8 and binary input survive deterministic child digest/count checks. Type assertions are not the oracle. This qualifies the current raw path independently of either queue remedy.
2. **Stalled reader:** finite byte/call count and hard test memory/time ceiling; child starts in a proven nonreading state then resumes; record synchronous public-return count, child eventual received bytes, RSS and event-loop progress. No internal instrumentation is silently introduced into the author's current allowed harness. Public evidence may show excessive accumulation but cannot identify exact private queue occupancy by itself. The source proof of uncapped queue remains valid even if the finite sample stays small.
3. **Failure/close semantics:** observe public outcomes on child exit during queued input, late output/exit and cleanup. A real harness may not deterministically force every fs.write failure; the selected remedy must later add a controlled writer fault seam to test partial success, EAGAIN, permanent error, in-flight close, callback after disposal and one settlement. Do not mutate global fs or trigger unsafe fd reuse merely to finish the first slice.
4. **Owned helper lifecycle:** normal exit, leader-only termination and explicit verified group termination, with final owned PID/helper verdicts. Record platform differences. Do not infer Linux from macOS, or a group guarantee from forkpty source alone.
5. **Chosen option validation after approval:** over-cap rejection before copy, concurrent user/query admission, partial write accounting, error without silent queue loss, no-replay results, bounded retry scheduling, and no descriptor use by later callbacks after retirement. Exact guards must fail on unsupported version/shape/patch mismatch. These are remedy acceptance tests, not claimed current harness results.

For 100 sustained PTYs, finite per-run input caps alone are insufficient: retain the worker aggregate cap, avoid one hot setImmediate retry loop per blocked writer, record retry CPU/event-loop effects and maintain progress for the operator run. Option A's polling would add recurring work and still lack error truth; option B's callback-driven writer avoids polling but its retry pacing still needs measurement. Ordinary two-to-four-PTY CI validates correctness and local fairness; it does not satisfy C5/X1. No devbox retry or 100-PTY run is authorized here.
