## Frozen design to implement

- SubscriptionRef is the sole routing identity: run, ConnectionRef, subscriptionId, viewId. No second numeric streamId. New attach/new view/new connection allocates a fresh non-reused ID within its connection scope; repeated completed recover on a live subscription preserves the complete ref.
- Inner RunEvent remains the immutable run/seq fact. Ordinary output/resize/control/appearance/exit delivery externally is `{type:'run-event',subscription,event:RunEvent}` with the same single raw payload. Validate outer ref/run/connection against inner event and negotiated session. No transcoding, duplicate VT payload, sequence reset or renderer envelope requirement.
- Keep renderer TerminalEvent and TerminalView.applyEvent unchanged. Define a separate external terminal-event union for wire class3 rather than forcing T2/V1 to unwrap transport routes. Baseline start/chunk/end already carry the ref; retain consistent binding. Preview uses its own run/previewId/version correlation, never a live subscription.
- recover-result contains original/current subscription, mode, atSeq and request correlation; remove replacement rather than retain a misleading alias. Recover command retains original ref/reason/resume.
- baselineId scopes one baseline transfer. Local recoveryAttempt/viewGeneration fences asynchronous work. Neither baselineId nor unchanged SubscriptionRef alone isolates old ordinary events or ACKs.

For baseline delivery require equality with its embedded ref if the outer member is present; preview has no live route. Use one canonical producer convention (ordinary+baseline carry outer route; preview does not), and reject inconsistent combinations. ## Serialized recovery contract; no wire generation added

1. One recover in flight per subscription. Client synchronously gates input, increases attempt token, cancels unsent old ACK/progress/timers and drops queued old apply work. Already-sent commands precede recover on the same ordered uplink; command dispatcher preserves that per-subscription effective order across awaits.
2. Old parser completion can settle its own call, but current connection/ref/attempt/view checks precede ACK, grant admission and any new view mutation. Pending uncertain parse makes retained-model replay ineligible; use a fresh backend baseline. Keep inputSeq/focusSeq monotonic across stable-ID recover, and never replay input.
3. Worker/server process recover as the uplink barrier: apply prior ACKs, invalidate old delivery producers/capture callbacks, retire old attempt ledger and unsent delivery queue. This does not assert old data was parsed. Physical bytes already buffered in pipe/socket/adapter remain counted until released.
4. Worker emits its accepted recover result before any new-attempt subscription delivery, through one ordered pipe queue. P2 processes pipe ingress in order and emits external recover-result before that new delivery through one ordered connection queue. An old callback must not publish across either boundary. Same-subscription control priority cannot overtake the marker.
5. Client discards old frames arriving after its local recovery start but before matching recover-result; it sends no applied ACK for discarded data. The server does not await those old ACKs to recover; it retired that ledger. The matching result is the downstream marker; no old-attempt delivery may follow it.
6. New baseline frames are contiguous for that subscription, no live interleave; progress returns credit only after parsing each ordinal. finishBaseline in current attempt commits atSeq and permits cumulative applied-ack. Replay emits contiguous facts from trusted appliedSeq+1 through result.atSeq, then live; empty replay completes at result. Do not roll back a previously proven applied cursor.
7. New credit ledger only returns retained current-attempt bytes once. Duplicate/over-high ACK cannot mint credit; equal seq across a baseline recovery must not reuse an old ledger. BaselineId isolates transfer progress; ordered uplink+local callback fences isolate applied-ack. Both are necessary.
8. Logical ledger retirement must not let outstanding transport buffers escape aggregate budgets. New recovery may wait for bounded transport capacity; control has reserved allowance. One slow subscription cannot block another eligible one or pause unrelated PTYs.
9. Stale focus/input responses may resolve their original outcome once, but cannot enable current admission. Recovery does not auto-focus/increment control epoch. A timed-out/unknown recovery retires that subscription; reattach uses a new ID. Do not overlap retries on the same ID while the prior marker's fate is unknown.
10. All asynchronous producer, service/capture, send-queue and parse callbacks check their owned local attempt; same wire ID is not a sufficient check. This must hold inside worker, runtime/server and client. Channel order alone cannot cancel producer callbacks that publish later.
    These are application barriers over the selected ordered transports, not properties supplied by SSH encryption. If a future change introduces cross-channel unordered delivery/concurrent recover, it must revisit generation requirements; this slice introduces neither.
