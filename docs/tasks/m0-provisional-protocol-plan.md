## Concrete provisional contracts

These values are provisional implementation defaults; P1b may revise them with coordinated consumers. Internal names may change, observable bounds may not silently weaken. No generic transport/schema registry.

### Identity and validation

- `RunRef = { serverId, relayInstanceId, runId }`; `WorkerRef = { serverId, relayInstanceId, workerId, workerIncarnationId }`. A pipe envelope containing both must have matching server/instance fields. IDs are opaque, case-sensitive ASCII tokens matching `[A-Za-z0-9][A-Za-z0-9._-]{0,127}`. This is a fixture-friendly experiment syntax, not a production ID generator; no random/crypto/environment dependency is introduced.
- Export Zod schemas and inferred types for these JSON-compatible objects. Missing, empty, oversized or mistyped IDs fail without trimming/coercion. Equality compares every constituent field; endpoint, PID, build, renderer, tab and workspace never substitute for them. Structural equality validates a reference, not ownership/authentication/liveness.
- Correlation IDs (`requestId`, `baselineId`) use the same bounded token syntax but retain separate field names and purposes. A request ID is only pipe attempt correlation, never an operation deduplication key or proof of execution. No pending-request map or liveness state.
- `seq`/`atSeq` are non-negative safe integers up to `Number.MAX_SAFE_INTEGER`; reject fractions, negatives, NaN/infinity and unsafe integers, with no wrap or increment helper. Carrying a sequence does not enforce monotonicity or establish a recovery boundary. Q1/T1 choose fixture values; worker ordering/overflow behavior is frozen in P1b.
- Known metadata is validated, unknown optional object fields may be ignored after the total metadata byte bound. Unknown kinds, lane/revision or required fields fail. No implicit defaults that turn missing identity into a valid reference; no coercion/transforms or opaque recursive JSON payload schema. Schemas remain exportable JSON subsets; cross-field comparisons are explicit validators.

### Terminal lane

Provide only four kinds, with a closed kind byte and matching metadata schema:

| Kind             | Metadata                                                               | Byte payload                                                                |
| ---------------- | ---------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| `output`         | `run: RunRef`, `seq`                                                   | Opaque VT bytes; including partial UTF-8/control sequences without decoding |
| `input`          | `run: RunRef`, `requestId`                                             | Opaque fixture input bytes; no provenance/authorization/epoch claim         |
| `baseline-chunk` | `run`, `baselineId`, `atSeq`, `chunkIndex`, `chunkCount`, `totalBytes` | Opaque baseline slice                                                       |
| `error`          | `run`, `error: { kind, message }`                                      | Empty                                                                       |

Use `chunkCount` 1–256, `chunkIndex` 0–`chunkCount - 1`, `totalBytes` 0–16 MiB. A zero-byte baseline has one empty chunk at index 0. Each nonempty baseline chunk has 1–64 KiB bytes; declared totals must be feasible for the count and this chunk's size. Do not allocate `totalBytes`, assemble, retain, reorder or promise completeness in the codec. Final cumulative length, missing/duplicate chunks, cancellation, interleaving, digest, recovery start/end and installation are consumer/probe concerns until P1b. Tests can assemble small synthetic examples outside the library to prove opaque transport.

Q1/T1 keep grid, parser-tail, history, query and profile annotations in local fixtures associated by baselineId, then propose proven metadata to P1b. Opaque transport does not prove recovery; no private xterm object enters this schema.

### Pipe lane

Closed kinds are `probe-request`, `probe-result`, `terminal-event`, `error`. Request/result carry `worker: WorkerRef`, `run: RunRef`, `requestId` and optional opaque fixture bytes. `terminal-event` carries the same worker binding plus one terminal `output` or `baseline-chunk` metadata record and its byte payload; there is no nested encoded frame. `error` carries worker/run/requestId and the bounded error object, with empty payload. All are probe-only correlation structures; no arbitrary method-name dispatcher, spawn/stop/control union or production hello/ready is added.

T1 can carry fixture output/baselines through the framing Q1 consumes. Actual pending-command matching/current-incarnation checks belong to consumers; fixture tests explicitly compare expected complete refs/requestId. No second Node message channel or runtime acceptance claim.

### Errors

Return discriminated local failures for invalid header/metadata, unsupported format/kind, capacity, identity mismatch, truncated EOF and closed decoder. Separately transmit only `INVALID_ARGUMENT`, `IDENTITY_MISMATCH` or `PROBE_FAILED`, with at most 256-character messages. Use fixed diagnostics/non-sensitive offsets; never echo metadata, VT, credentials or parser exception text. No RPC error allocation, retry flag, replay or liveness inference.

## Bounded byte framing and API behavior

Use a 16-byte experimental header: two magic bytes `0x43 0x50` (`CP`), one lane byte (terminal 1 / pipe 2), one lane revision byte, one kind byte, three reserved zero bytes, uint32 big-endian metadata length, uint32 big-endian payload length. Each lane has its own exported provisional revision constant, initially 1, independent of build and future bootstrap/business versions. Assign kind values consecutively in each lane in the table order above; values have meaning only within that lane. Do not freeze these allocations as production opcodes.

Limits: metadata 1–4096 bytes, payload 0–65,536 bytes, complete frame at most 69,648 bytes. Reject bad magic, reserved bits, lane/revision/kind or lengths as soon as the header is complete, before allocating a body. Header/body arithmetic must not truncate or wrap. Encoders enforce the same ranges before allocation and respect typed-array offsets. Output/input zero-length payloads remain legal; the empty-payload and baseline cross-field restrictions above are enforced when combining decoded metadata with its payload.

The codec accepts and returns Uint8Array only; no Buffer, stream, socket, TextEncoder/TextDecoder, process, timers, NodeJS or DOM types in package sources or public declarations. Host code performs UTF-8 encode/decode and JSON stringify/parse around the exported metadata schemas. On receive it must use fatal UTF-8 decoding, parse only a completed metadata slice of at most 4096 bytes, validate the metadata for the header kind, and enforce metadata/payload cross-field constraints **before delivery**. A framing result alone is not a validated message. On send it validates metadata first, serializes it, then checks encoded byte length in the frame encoder. Provide a short compiled-consumer fixture demonstrating this exact composition; no custom UTF-8 implementation or codec dependency is justified.

The decoder takes the expected lane/revision when created. Each `read(input)` returns `{ consumedBytes, frames, status }` (equivalent spelling is acceptable), with at most 32 frames and 256 KiB of emitted complete-frame bytes per call. It consumes at most 256 KiB of caller input per call, stops before exceeding output limits, and retains at most one incomplete frame. Large/coalesced ingress is processed incrementally; the caller retains and resubmits the unconsumed subarray, choosing scheduling itself. Do not append the whole input, retain its backing buffer after returning, or return an unbounded array. Completed output buffers are independent of caller input and reusable decoder storage. Internal storage must be bounded by one maximum frame plus fixed bookkeeping; no unbounded segment array for one-byte input and no repeated concatenation of the whole pending frame.

Report progress so a host can distinguish more input from budget exhaustion without a busy loop. Empty input is a no-op while open. `finish()` succeeds only with no partial frame; otherwise return `TRUNCATED_FRAME`. Fatal framing errors release retained storage, close the decoder and report the failing byte boundary/consumption without delivering the invalid frame or anything after it; already completed preceding frames may be returned explicitly. Reads after failure/finish fail as `DECODER_CLOSED`; recovery uses a new decoder. No resync scan, swallowed error, callback, side effect or automatic retry. Caller-owned returned frames/ingress are not a codec queue; the host must release or bound them in its eventual transport.
