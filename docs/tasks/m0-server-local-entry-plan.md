This implements the already approved private D boundary in P2 R2. It adds explicit numeric-loopback local options; a passive Fastify application factory used by the compiled entry; HTTP bootstrap and the six fixed RPC methods; terminal WebSocket first-message authentication and existing binary command service; per-launch secret and restricted rendezvous; installed public worker-bin stdin/stdout adapter; and one local monotonic timer driving existing session, preview and connection deadlines. It adds no remote mode, persistent pairing or new protocol.

The selected pins are Fastify5.12.5, @fastify/websocket11.3.3 and @types/ws8.18.2, with workspace protocol/worker dependencies. Node26.10.0, pnpm12.6.0, TypeScript7.0.2 and existing native pins stay unchanged. The dependency-only install uses ignore-scripts; this author allocation never installs or launches a native worker. Framework behavior is checked against official Fastify content-type/server documentation and the websocket plugin documentation. Orca322c1839 `src/main/runtime/rpc/ws-transport.ts` is comparison only: its carrier ownership separation is useful, but its remote auth, caps, heartbeat and fallback policy are not Cove contracts.

The actual private method map is server.status to cached pool/registry/composition facts; terminal.list and terminal.get to preview-cache metadata; terminal.create and terminal.stop to TerminalOperations; operation.get to its receipt lookup. The existing classifier, parameter/result/correlation validators and response composer remain authoritative. Notifications have no business effects. Every RPC request rechecks protocol/server/instance headers; bootstrap does not replace this guard. Body readers enforce actual received bytes and reserve in-flight ownership before parsing.

Host must equal the actual numeric bound authority. Every present Origin must exactly match configured origins, including CLI-classified requests; null is forbidden. Actual fetch headers classify browser HTTP requests, which require Origin. CLI HTTP absence still requires the secret, while WS absence enters only unauthenticated first-message admission. OPTIONS is restricted to the two POST routes and fixed header set. The random secret appears only in the restricted local rendezvous and private authentication inputs, never negotiated/business responses or diagnostics.

Transport claims charge conservative fixed reader/carrier reservations to the same runtime ledger: RPC request cap+4096B until domain completion, bootstrap cap+4096B for unauthenticated WS, and two maximum terminal frames+4096B for authenticated WS until actual close. These are ownership reservations, not measurements of every Node heap allocation. Promotion acquires auth ownership before retiring unauth ownership. A requested socket close is not a physical-close or process-exit receipt. Worker contact loss never proves run or descendant exit, and D does not release owned run capacity from socket events.

Rendezvous publication creates a task-owned same-directory exclusive 0600 file, writes and syncs complete bytes, then atomically links it to an absent final path. Existing foreign files are preserved. Cleanup compares owned inode identity before removal, retains failures, and never removes an unrelated replacement. The installed worker adapter uses the public package bin with shell disabled; only directly observed child exit and stream-close events supply their respective receipts.
