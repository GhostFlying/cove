# M0 browser probe cleanup deadline results

Status: locally verified cleanup-budget repair on macOS arm64, 2026-09-26. Source base is `a111a7ca9821ef903ca108d69304600866c683a0`; the final repair commit SHA is reported at handoff. Hosted macOS/Linux CI and independent review of this repair remain coordinator gates.

PR #33 run `36186368871` supplied the trigger: Linux passed, while the macOS query-only browser test completed its action phase but failed cleanup with one `Query fixture disposal timed out` error. The fixed 500 ms per-page disposal timeout was shorter than the available seven-second cleanup budget. The hosted log has no disposal duration or resource contention trace, so it cannot distinguish a slow xterm disposal from delayed runner/browser scheduling. The fix reallocates the **same seven seconds** for Q1: up to 3.5 seconds shared fairly among owned pages, graceful browser close ending at 4.5 seconds, a reserved kill interval ending at six seconds, and a final second for listener closure and evidence. Page disposal receives its share after reserving page close, capped at 1.5 seconds; unused time carries forward. B0's original 500 ms page-operation caps and browser/listener limits remain unchanged. Errors are still collected, including page disposal and process/listener failures, and the browser is killed if graceful close fails.

The compiled probe adds a two-page cleanup-only scenario. A test-only browser evaluation delayed each page's disposal by 700 ms, exceeding the previous 500 ms limit; it succeeded with both pages closed, browser process exited, listener closed, and `cleanupElapsedMs: 1587`. A separate run made the first page's disposal promise never resolve: it reported `Query fixture disposal page 1/2 (1249 ms) timed out`, then closed both pages and reaped the browser/listener in `cleanupElapsedMs: 1419`. A third run made graceful browser close never resolve; it reported `Browser close timed out`, executed the real `BrowserServer.kill()` path, and still recorded both pages closed, browser process exited, listener closed, and `cleanupElapsedMs: 2175`. These observed times are local measurements, not hosted CI-load reproduction. Each failure remains visible; neither hang is retried or treated as a pass. The runs used the pinned Chromium revision `1243` / `153.0.8010.12`, Playwright `1.63.0`, Node `26.10.0`, pnpm `12.6.0`, and task-owned browser/install paths.

After a frozen install and browser installation in the isolated checkout, `pnpm --filter @cove/terminal-web --fail-if-no-match test` passed 15/15 tests (Q1 10, B0 5), including delayed/hung cleanup and existing work-plus-cleanup failure cases. `pnpm exec oxlint --deny-warnings packages/terminal-web/probes`, Prettier and `git diff --check` passed. The test-only scenario does not change query/input adapter behavior or the registered suite count. The final integrated CI must still show the query-only corpus and cleanup passing on both hosted operating systems; this local result does not erase the failed macOS run.
