## J: final-glyph-last, a specific checkpoint candidate

Pinned evidence: `InputHandler.ts:507–665` maps charset, computes Unicode properties, applies wrap/insert/scroll effects and finally stores `precedingJoinState`. `EscapeSequenceParser.ts:650–692` clears that state for EXECUTE and completed CSI. `UnicodeService.ts:20–31,34–38` and `UnicodeV6.ts:132–145` show the pinned default provider's width/join calculation. `InputHandler.ts:1590–1625` makes REP consume the preceding width and the cell behind the current cursor. Thus finishing restoration with SGR/CUP discards the very state a following combining glyph or REP needs.

Try this narrowly:

1. At a settled complete UTF-8/parser boundary, read the retained cell/cluster and its public width/text/style near the current cursor, plus the existing guarded read-only current/saved state. Maintain at most a bounded final-print witness if actual input bytes are needed; do not retain the entire printable run. Include the witness in existing checkpoint/tail accounting.
2. Construct the receiver's content preimage and restore both-buffer geometry, registers, modes, margins, charset and current pen **before** the last print. Position at the intended cluster start. Emit the final cluster as the final baseline bytes; no CUP, SGR, mode switch, query or other escape follows it. Any pending parser tail follows only as the original source bytes, in its original order.
3. Await completion, compare source/receiver cells, cursor/wrap/register behavior, and the pinned private join-state read as a diagnostic. Then test immediate suffixes on separate fresh restores. Do not query CPR before the combining/REP suffix: doing so resets state and can hide the defect.
4. Replace the old checkpoint and clear its tail only after the candidate has passed the complete boundary checks. Continue live authoritative parsing unchanged if a candidate is rejected; report the resulting ordinary-case blocker rather than silently discarding tail bytes.

Start with last ASCII `A` in ordinary replace mode, then a complete wide character, base-plus-combining cluster and DEC charset mapping. Public cell contents are enough to propose bytes for these cases, but not automatically enough for all print histories: they contain rendered characters rather than original source bytes, and a resize can move/clamp the cursor without resetting the preceding state. The private **read** identifies the candidate condition and can verify it; it does not justify writing the scalar into the receiver or sending it over the wire.

Required small matrix:

- Stream at least 131,073 `A` bytes in bounded chunks through normal and alternate buffers, at two dimensions including a final-column cut. Show at least two successful checkpoint replacements before old-tail capacity is reached, recover at each, and keep tail/temporary memory bounded. Ordinary output never becomes unavailable. The two checkpoints must be real independently restorable outputs, not just reset counters.
- At interior and pending-wrap positions, compare immediate printable, combining and `CSI 3 b` suffixes, plus saved-cursor restore. Include the bottom scroll margin and a nondefault pen/charset.
- Test insert mode and wrap disabled, including a width-two character attempted at the last column. Source `print()` updates the candidate Unicode state before rejecting an overflowing wide glyph in wrap-disabled mode; the relevant state need not correspond to the visible last-written cell. Capture the exact counterexample if a cell-derived witness cannot reproduce it.
- Repeat with chunk splits within multibyte UTF-8 and the final cluster; only complete boundaries may refresh. Replay of an incomplete tail must not double-apply side effects. Retain the already passing parser/query matrix unchanged.

Printing is not an idempotent cell overwrite: IRM shifts the row; wide-character cleanup alters neighbors; final-column printing may wrap/scroll. For IRM, the generator may need a small row preimage so the final insertion produces the target row. Try a concrete bounded inverse for the authored case, not a general inverse-terminal solver. If the original last-print witness is required, its maximum bytes and exact relation to the current cell/cursor must be measured and validated. An arbitrarily long combining cluster is not evidence that constant-size metadata always suffices; account for its bytes within retained state/checkpoint limits and report budget conflicts explicitly.

**J stop condition:** after the ASCII refresh case and this finite matrix, either publish exact passing fixture/cut counts, or preserve the smallest failing prefix/state/suffix and identify whether the obstacle is missing read information, a different required content preimage, or inability to express the state with the tested receiver actions. No repeated tail-cap increase, fake join-state zero, receiver-private assignment, or relabeling ordinary output as pathological. A failed simple candidate does not prove all VT reconstruction impossible.

## G: compose the public geometry recipes before considering a fork

Use two combined fixtures, not a broad search:

1. Alternate active at logical 40 with mixed row lengths 40/41 (both orders), a retained-edge sentinel and styled wide/combined/blank cells. Hidden normal has ordinary wrapped content, distinct saved cursor/pen/charset and custom margins. Reconstruct, perform same-grid ICH/DCH, exit alternate, restore saved cursor and continue normal.
2. Repeat with the 3-line retained-history budget and a leading wrapped row, using the reported disposable-row technique; verify exact coverage and absence of the dummy row. Include later 40→41→40 and a same-size resize after installation, with authoritative baselines where the accepted history rule requires them.

Choose one concrete normal-buffer preimage at the temporary reconstruction width, then apply the alternate row replacement schedule and final resize. Treat the dummy-row recipe as one candidate for leading wrapped context. Verify the **entire** hidden normal state after the geometry schedule, not only a separately restored normal fixture. Then compose one G result with J's final-glyph-last step and an immediate continuation; separate component passes are insufficient.

Keep dimensions within the existing 120×40 experiment budget; count geometry operations and every temporary row/cell/encoded copy against declared bounds. Receiver-only resize/write steps are ordered installation operations, never PTY resize, authority geometry, focus or query output. Compare the source before/after generation and ensure the receiver remains unavailable for input until installation commits. No private source mutation, destination cell/register assignment, new protocol schema or permanent mirror.

**G stop condition:** give the two public recipes one explicit combined implementation attempt and a minimized correction justified by observed divergence, then freeze the outcome. If normal reflow/coverage or alternate capacity still diverges, retain the first differing cell/line length/wrap/register and exact suffix. Do not call the problem impossible or start an unbounded search for an inverse normal-buffer image. A neutral installation schedule is a legitimate profile detail, but its existence must be proved for the required cases.

Conversely, no user decision is needed now to try the two public techniques. Escalate a specific demonstrated tradeoff after these results, not a speculative choice between a hypothetical perfect public serializer and an unspecified small patch.
