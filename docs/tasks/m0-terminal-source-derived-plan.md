## Recommendation

There is **not yet a required user architecture decision**. Make one finite, source-derived construction experiment before choosing a dependency patch or weaker semantics. It must use one fixed algorithm and independently varied inputs, not another round of literal fixture repairs. Passing this experiment would justify further implementation/qualification of that algorithm; it would not establish universal recovery or freeze P1b.

The motivating goal is avoiding a fast-moving application fork. A small, tested dependency patch might eventually be cheaper than maintaining a custom inverse-reflow/serialization algorithm; neither is maintenance-free. Compare their actual surfaces after the finite experiment, without claiming that an untried public recipe is impossible or that a restoration patch is trivial.

## What is actually established

J demonstrates 20 fresh checkpoints of ordinary ASCII streams and authored final-print continuations. Its `FinalGlyphWitness` still receives bytes, location, width and preimage type from fixtures. Its 64-byte sublimit rejects an ordinary 67-byte cluster despite the 8 MiB baseline budget.

G demonstrates bounded public VT representations for its combined examples, including J composition. It does not supply an automatic generator. In `recovery-geometry.test.mjs`, `installCorrection` branches on fixture kind/shortRow, writes a literal missing `N` at row 2 column 24, supplies a literal styled edge blank, sets a known off-grid tab, replaces an authored short row, and optionally appends a known final `Q` sequence. Those operations were validated against full public/private state, so the result is stronger than a screenshot and weaker than source-driven recovery.

Required R5/R6 acceptance remains unqualified. The source observations do not prove that wider retained columns or combined buffers are unrepresentable with public VT/geometry. They prove current-width serialization alone is insufficient and that several representations depend on information/derivation the candidate has not automated.

## One finite experiment: source-only construction

Proposed scope: one probe-local generator, reusing existing VT register restoration, pinned read boundary and byte/tail handling. No production schema, engine patch, observer hook, dependency change or generic search framework in this experiment. Input is the settled source terminal plus explicit profile/budget options; output is bounded VT and ordered receiver geometry operations. No fixture ID, original setup stream, known final glyph, repair coordinate, expected snapshot, receiver oracle or history transcript is an input.

Freeze this construction rule set before evaluating independent variants:

1. **Capture:** read logical geometry, both buffers' public retained cells, per-row storage length and wrapped flags; read unavailable current/saved registers, tabs/charset and join information through the existing guarded module. These are bounded local observations, not wire cell arrays or private state installation. Capture at a settled source event boundary without resizing/mutating it.
2. **Geometry/content:** derive temporary width from actual retained extents. Build a normal-buffer preimage by grouping retained rows on hard/soft-wrap boundaries and packing each logical run into the temporary width, preserving null versus literal space, styles and complete wide/combined cells. Use at most one disposable leading row when the retained first run begins inside an earlier wrapped run. Map current/saved cursor anchors explicitly rather than inserting the known missing `N`. This is a concrete hypothesis, not a guarantee that resize/reflow has a unique inverse.
3. **Alternate topology:** emit its retained cells at the appropriate temporary width and recreate shorter physical rows using the already tested DL+IL operation, selected from observed row lengths. Repaint those rows from source cells; derive edge blanks and tabs from source, not fixture labels. Use a deterministic descending-width schedule if more than one retained width is admitted by the probe; do not search permutations. Every temporary resize affects hidden normal, which must remain part of the comparison.
4. **Registers and final print:** restore explicit state in the tested order and return to authoritative dimensions. Derive a canonical last-print witness using current cell/width/modes/join state and only the finite J recipe families: ordinary overwrite, IRM delete-preimage and equivalent rejected-wide print. Validate their preconditions; do not guess stale coordinates after resize. Emit the final cluster last. Account for the full ordinary cluster inside the baseline budget instead of keeping the arbitrary 64-byte ceiling. A state lacking a proved rule is a recorded experimental failure, not accepted production unavailable behavior.

The generator must not launch a receiver, compare differences and emit repairs until it matches. Receivers belong to independent verification only. Otherwise the experiment becomes a potentially expensive inverse solver and the oracle becomes part of production behavior. One deterministic output for the same captured source is required; equality after a reconstruction search is not acceptance.

### Finite challenge set and stop condition

Use all existing J/G cases and one fixed, unpublished-to-the-generator set of eight deterministic variations chosen by the independent tester. Variations cover width pairs other than 40/41, short-row placement, changed sentinel text/styles/tabs, normal wrapped history (full and three-line budget), saved charset/pen/margins, and J joined/IRM/rejected-wide states. Add the 67-byte cluster and print→resize→checkpoint. At least one test combines geometry with final-print continuation. The generator cannot receive seeds or variation descriptors.

Check pre-suffix state and immediate same-grid edits, combining/REP, alternate exit, saved-cursor continuation and subsequent resize. Include repeated checkpoint replacement on 131,073 ordinary `A` bytes, fresh receivers, source/reply purity, incomplete UTF-8/parser tail rules and unchanged mandatory suites. Expected sentinels and an independent public/private oracle remain separate from generation. Preserve current 120×40/1000-history/8 MiB baseline/64 KiB tail limits, with explicit operation, cell-scan and temporary-copy accounting; passing a few small examples is not a memory or CPU bound.

**Stop after this one algorithm and one minimized, generally applicable correction tied to a demonstrated invariant.** No added fixture-name branches, literal repairs, receiver-diff search, new patch or expanded profile. A correction must be derivable from source for every case it affects and rerun the whole finite set. If a normal preimage, final witness or bound remains unresolved, freeze the first failure and the precise missing rule/information. Do not continue an indefinite series of special cases. Nor does that failure prove every public algorithm impossible.

This experiment can fail usefully: distinguish (i) insufficient observations, (ii) a flaw in the chosen preimage construction, (iii) a tested public action that necessarily alters another required state, and (iv) unacceptable algorithmic/budget cost. Each supports a different next decision. A finite pass is evidence for a parameterized algorithm, not arbitrary-state completeness; independent review must still compare its supported conditions with every accepted T1 requirement before P1b.

An addon serializer patch that merely visits more columns cannot solve fresh-receiver storage or both-buffer coupling by itself. A B1 observer cannot manufacture a valid B2 installation sequence. Conversely, G's component successes mean B2 is not yet shown necessary.

For B2, the bounded design proposal would need to identify the exact state that public operations cannot preserve under the selected construction, the smallest neutral receiver action that avoids that transformation, failure rollback/disposal, and an estimate from actual source diff. Do not describe a new transactional restoration API as a tiny patch before this assessment. The user may reasonably prefer a focused dependency patch to a complex custom generator, but needs that comparison rather than a blanket aversion to all patches.

## Invariants and approval boundary

All preservation paths must keep the sole live authority unchanged; bind baseline to exact run/event identity; retain both buffers' required state; install VT plus explicit neutral metadata; suppress receiver automatic replies; leave genuine input under the controller's readiness rules; commit only after final logical geometry and complete restore; replay tail exactly once; and remain bounded without a permanent second live model or unlimited raw log.

Ordinary source-derived experiment, a measured budget correction for a 67-byte cluster, and read-boundary clarification need no new user permission. A modest, evidence-driven dependency adaptation may fit existing architecture, but moving to a maintained hot-path/transactional API is a material engineering commitment: present its concrete patch and upgrade cost against the demonstrated custom-algorithm burden before choosing it, especially given the user's maintenance goal. This decision need not wait for a mathematical impossibility proof; it does need an actual failure/cost surface rather than speculation.

Any weakening of fresh recovery, loss of retained state, changed authoritative resize/edit behavior, private-object/cell-grid wire format, or permanent mirror/unbounded journal requires explicit user approval. None is recommended now. T1 and P1b remain unqualified until source-derived behavior and the required matrix are independently verified; green fixture-specific J/G tests do not close that gate.
