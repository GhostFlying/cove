## Candidate and public-API counterexample

The candidate installs a probe-local adapter before any output reaches xterm. It forwards only core data marked `wasUserInput` and raw `onBinary` mouse bytes to the outbound sink; it observes but suppresses unmarked automatic data. It does not classify by reply text, by a write-duration flag, or by an input pause. Parser queries, focus reports, and actual user input are recorded as distinct observations. Focus `ESC [ I` and `ESC [ O` were observed and suppressed, but are **not** claimed to be query replies; their production policy remains open.

Public parser handlers can consume a whole OSC sequence, but OSC 4 `ESC ] 4 ; 1 ; #aabbcc ; 1 ; ? ESC \\` both sets a palette entry and asks for its value. In the public-hook control, consuming it left palette entry 1 at `[1,2,3]`; delegating it would allow xterm's reply into `onData`. The private-origin adapter preserved the setter as `[170,187,204]`, suppressed the reply, and an OSC reset restored `[1,2,3]`. This concrete mixed-sequence failure is why the experiment uses source provenance instead of a public whole-sequence suppression handler.

The exact private surface is `Terminal._core.coreService.triggerDataEvent(data, wasUserInput)`, `triggerBinaryEvent(data)`, and `onUserInput(listener)`. The adapter checks the actual installed `@xterm/xterm` manifest version injected into the Vite bundle, currently `6.0.0`, plus callable/disposable shape, duplicate installation, synchronous user-signal behavior, nested calls, and wrapper ownership at teardown. An isolated build claiming bundled version `0.0.0` failed before input admission and still closed its browser/listener. Upgrading xterm requires inspecting these members and rerunning this browser corpus; the guard is intentionally exact, not a general compatibility promise. The legacy binary path preserves byte `0x84` as one byte rather than UTF-8 encoding it as `0xc2 0x84`.

## Observed corpus

The test fixture authors expected replies from pinned xterm handler behavior independently of the adapted sink. Each query was delivered through compiled `@cove/protocol/provisional/terminal` frames to both an unadapted reference and an adapted terminal. The 14 IDs were `dsr-status`, `cpr`, `dec-cpr`, `da-primary`, `da-secondary`, `mode-report`, `mode-report-reset`, `color-fg`, `color-bg`, `color-palette`, `color-cursor`, `dcs-status`, `dcs-margins`, and `window-report`. All 42 live/baseline/replay occurrences produced the authored exact reply arrays on the reference and empty outbound arrays on the adapted page. Baseline used a fresh terminal, then checked its continuing display cell and mode state. A coalesced query schedule around a held parser and queued write produced 387 reference reply bytes and zero adapted bytes. All write callbacks completed.

The action and byte observations are recorded by the tests under `.cache/ci/smoke/query-input-*.json` (eight bounded JSON files, generated rather than committed). The decisive samples are:

Disposing during a held parser completed the old write without outbound input; a replacement terminal emitted only its new `r` input. Duplicate attachment, wrong version, missing private surface, nested `x/y/z` callbacks, and old-wrapper teardown all passed their explicit checks. Compiled protocol validation rejected 14 wrong-identity, missing/duplicate/reordered/inconsistent chunk, over-limit, and invalid UTF-8 inputs before browser delivery (`delivered: 0`). The two added overfull cases assert rejection before appending a second individually valid chunk, including two 65,535-byte chunks claiming a 65,536-byte total. Injected work and cleanup failures retained both errors; a held-barrier deadline released the parser. A page error injected after fixture readiness failed the scenario, as did a Unicode result whose JSON has fewer than 256 KiB UTF-16 code units but more than 256 KiB encoded UTF-8 bytes. The cleanup assertions observed process exit and listener closure in all failure paths, and the normal runner verified the bound listener was unreachable after return.

The experiment uses a synthetic DOM paste event, not the operating-system clipboard. It reads browser buffer/mode and private color state, rather than measuring rendered pixels. It tests the chosen deterministic fixture modes and bounded frame envelope, not every xterm extension or future xterm release. It does not establish real PTY, zero/one/two-client reply authority, recovery admission, mobile IME, or SSH behavior; those belong to later M0 work. No required Q1 case was skipped or marked unavailable.
