## Why this particular boundary

Pinned `BufferService.resize` updates global parser dimensions and invokes `BufferSet.resize`, which resizes **both** buffers and sets up both tab maps. `Buffer.resize` can reflow normal history, clamp current/saved cursors, reset margins, grow row storage and trim history. Alternate shrinking retains wider physical rows under the selected profile, and `BufferLine.insertCells/deleteCells` use that physical length. Therefore replaying at a temporary width is meaningful, but the ordinary global resize also changes hidden normal state.

G's committed `installCorrection` repairs a literal missing normal `N`, a styled alternate edge blank, tabs and a short row using fixture knowledge. Its successful assertions establish representations for those examples, not a generator or a general inverse. A serializer-only change cannot eliminate the receiver's coupled resize; a geometry API cannot recover a cell the generator omitted.

`BufferSet.activateNormalBuffer` copies the alternate cursor and clears alternate storage. `activateAltBuffer` copies the normal cursor into alternate. A general non-clearing buffer selector would introduce another semantic operation. Avoid that in the first proposal: construct normal first, enter alternate once if it is the source's active buffer, finish there. When source is normal-active, its ordinary switch has already cleared alternate content. Any additional retained inactive-register obligations still require explicit validation; do not silently drop them because its cells are empty.

## Smallest proposed interface and installation order

The API is an installation capability on a **new, inert receiver**, not a new ordinary `Terminal.resize` behavior. Conceptual operation: “set alternate reconstruction columns to W, keeping logical rows fixed and leaving normal completely unchanged.” The actual API name and wire fields are intentionally not frozen here.

1. Construct the receiver at final logical columns C and rows R, with the agreed history budget and engine options. Restore normal content/history and normal saved registers at C. Do not expose the staging receiver or connect it to PTY output/input/control events.
2. If the source is alternate-active, enter alternate through the existing VT path. In an explicit installation session only, permit changing active alternate reconstruction width to W. Set parser geometry consistently and resize **only alternate**, never call the ordinary both-buffer resize. Preserve normal contents, line lengths, wrapped flags, cursors, saved registers, margins, tabs and history indices exactly.
3. Emit source-derived alternate VT at its required retained widths. Return alternate and parser geometry to C, maintaining the selected profile's retained storage behavior. Recreate genuinely shorter rows using a proved bounded recipe and restore alternate registers affected by resizing. Current-grid tabs must be generated from source and restored in an order that avoids introducing defaults; omitted off-grid stops require the explicit resize-context treatment below.
4. Finish at C×R; complete register restoration and final-print witness in the proved order. No subsequent VT may reset the required join state. Drain ordered writes, validate installation completion, then publish the new receiver and replay the bounded tail exactly once under the normal readiness contract.

Restrictions make this smaller: no row-count changes, arbitrary inactive writes, non-clearing selection, private cell import, general reflow toggle, authoritative-side invocation or in-place rollback. Operations occur only between settled writes, while the active buffer is alternate. Temporary width is explicitly bounded. Changing buffers or issuing geometry-changing VT inside a staging segment must either be structurally excluded by the generated stream or rejected by the installation machinery; the global parser width cannot be left inconsistent with the newly active buffer. Closing installation rejects further staging operations and verifies both buffers' logical dimensions agree with C×R.

A concrete implementation assessment must decide whether the session guard lives in a small public wrapper plus internal service method or in the engine. It must not rely on undocumented external assignment to `_bufferService.cols`. The neutral installation contract describes temporary geometry and ordering, not xterm classes or private arrays.

## Saved state, history, failure and remaining limits

Normal reconstruction at C avoids the temporary alternate resize changing its saved cursor, margins and history. It does not solve truncated leading wrapped history: the proved disposable-row approach or a separately justified neutral coverage mechanism still needs generic derivation and correct eviction. History budgets include temporary rows and copies. Alternate resize still clamps its own cursor/saved X and resets margins, so those must be restored after geometry, with saved charset/pen preserved. Final current cursor/pending wrap and J's join witness remain ordered last. **Retained off-grid tabs do not presently justify a second API.** My earlier brief incorrectly promoted private-map equality into a mandatory restoration operation. The accepted architecture (`docs/terminal-architecture.md:98–102,185–189`) and T1 plan (`55c59b1`, oracle and R2/R6) require observable continuation and allow an authoritative fresh baseline when resize context is insufficient. They do not require identity of every private implementation field independently of behavior.

Pinned `Buffer.ts:580–597` clamps `nextStop` to columns minus one; a stop at or beyond the width cannot move HT/CHT farther. Backward traversal starts below the current cursor, and `InputHandler.ts:823–827,1097–1122` returns before tab movement when the cursor is wrap-pending at or beyond logical width. Tab set/clear modifies current positions or clears the whole map, without moving retained off-grid keys into visible positions. The inspected common-source tab consumers expose no same-grid report of those keys. Under this pinned profile, I found no same-grid suffix that distinguishes maps differing only at positions greater than or equal to logical columns. This is source analysis, not an executed universal proof.

The maps can matter on a subsequent resize: `setupTabStops(newCols)` examines the boundary key and previous stop while creating defaults. Consequently omission must be recorded as insufficient resize context, and the receiver must install the authoritative new-size baseline before continuing, including row-only size changes where that setup path runs. It cannot claim full-context autonomous local resize equivalence. Both headless/browser public resize short-circuit unchanged dimensions, so an ordinary same-size resize does not itself expose this difference. Reassess if supported engine behavior or tab-report capabilities change.

Keep visible custom tabs and every demonstrated same-grid effect mandatory. Retain off-grid map comparisons as diagnostic evidence with an explicit equivalence classification, not an automatic acceptance failure; preserve strict public cell/style comparisons and the required suffix oracle. Do not suppress unrelated private differences wholesale. Exclude a tab-list setter/metadata extension from this proposal unless a concrete observable obligation that the accepted resize-baseline path cannot meet is demonstrated. This narrows implementation scope without weakening accepted recovery.

Use a fresh receiver so failure means **dispose the staging instance**, cancel its listeners/pending work and discard that installation's bounded queues. The prior display can remain visible but must not be represented as recovered/current or granted new input readiness. Retry uses a fresh baseline identity; no partially installed receiver reaches the PTY. Temporary resize, title/bell/query replies and buffer-switch notifications must remain local; genuine controller input is a separate path. Avoid live-object rollback and its substantially larger invariant surface.

This API cannot establish source witness provenance, serialize omitted styled cells, repair invalid UTF-8/parser boundaries, provide arbitrary cluster bounds, solve every mixed-width row topology, or prove normal current-width VT correctness. It also cannot guarantee an arbitrary renderer supports the neutral operation without an adapter. No source behavior is changed and no private-cell wire is proposed, but complete browser/headless recovery remains an acceptance obligation.

## Maintenance choice and next decision boundary

- **Continue the public algorithm:** retain upstream packages, but own inverse row packing, wrap/cursor-anchor mapping, null/style/combined-cell preservation, topology schedules and bounded generation. These depend on evolving engine behavior even without a source patch. After the agreed finite experiment and one correction, more inverse-reflow work is a new scoped cost decision, not an endless series of fixture repairs. The failed candidate does not prove all public algorithms impossible.
- **Adopt the narrow installation API:** own a source delta, reproducible packages/types, lifecycle and event isolation, browser/headless conformance, upgrade conflict review, and compatibility negotiation. Test unchanged ordinary resize/print behavior and failures/cancellation as well as recovery. It removes normal/alternate geometry coupling from this construction; it does not remove serialization and witness work. Actual diff review is needed before calling the patch small or estimating its ongoing burden.
- **Accept weaker recovery:** current-visible-grid restoration loses demonstrated same-grid DCH/ICH behavior; clearing hidden cells changes uninterrupted authoritative behavior; application redraw is not guaranteed recovery. These require explicit product/acceptance changes. Increasing an unbounded journal or keeping a permanent mirror does not meet the accepted constraints.

Use the verified frozen independent report and exact revision above, then present the first two engineering choices and the explicit weaker-behavior alternative to the user, with this limited API as the preferred patch candidate for assessment. The reported normal losses support investigating buffer isolation, not claiming it already fixes them; the styled alternate mismatch still requires correction of source-derived VT generation. Do not adopt it or launch another open-ended generator effort based on this memo. A maintained dependency adaptation is not equivalent to maintaining the original fast-moving application fork, but neither is it free. Its concrete ownership and reduced algorithm burden are the decision; changing source semantics or weakening recovery is a separate, unequivocal approval boundary.
