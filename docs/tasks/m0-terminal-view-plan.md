## Frozen operation semantics and P3 agreement

Use the exact `packages/protocol/src/view.ts` signatures at the base. Do not add ACK, epoch, `onGeometry`, socket, run status or backend state export. A structural fake TerminalView in P3 tests is sufficient for that branch; V1 qualifies the real browser implementation independently and H1/C3 later joins them.

One live view holds at most one xterm model and one pending parse operation. State is `new`, `initialized`, `installing`, `ready`, `failed` or `disposed`, plus an internal backend incarnation counter. The external `viewGeneration` comes from P3; it is not the internal counter. Listener subscriptions belong to the view object; engine/DOM callbacks capture the exact initialization generation and internal incarnation. `onFailure` has no generation in its payload, so closure fencing is mandatory.

## Provenance and input behavior

Promote Q1's proven strategy, not the failed public OSC-swallowing experiment. Guard actual pinned xterm 6.0.0 and callable/disposable `_core.coreService.triggerDataEvent`, `triggerBinaryEvent`, `onUserInput` before first output/input. Suppress `triggerDataEvent` when `wasUserInput` is absent/false in every phase. Do not forward an unclassified onData fallback, match reply strings, suppress all data during writes, or consume entire query-bearing OSC sequences. Mixed setters/reports must execute their setter effect while producing zero outbound automatic bytes. Automatic mode-1004 focus reports are suppressed too; their server policy is worker-owned.

For qualified text input, preserve Q1's synchronous `onUserInput` conformance check and nested-call behavior. Encode UTF-8 exactly once. For the binary mouse path validate byte values and preserve 0x80–0xff as single bytes; never TextEncode a binary string or forward it again through onData. Restore only wrappers still owned by this attachment; retired wrappers cannot act on a new backend. Guard failure yields PROFILE_UNSUPPORTED, closes the candidate backend and admits no data. A version increase requires rerunning the complete production browser origin corpus; a range check is not conformance evidence.

`InputIntent.source` additionally distinguishes keyboard/paste/mouse. Core `wasUserInput` is the authority that an emission is user input; browser event context supplies only its subtype. Before xterm handles the target event, record a bounded generation-scoped source context for paste, pointer/mouse/wheel, keyboard/beforeinput/composition. Use at most one synchronous event turn of tagging with cleanup on all paths; stale context must not cross initialization or a later task. Keyboard/IME encoding remains xterm's responsibility. Mouse-generated alternate-screen arrow sequences are mouse origin even when their bytes resemble keyboard arrows; reply-shaped paste remains paste. Do not infer subtype from VT grammar or install a second encoder. The pinned source/event schedule must be inspected during implementation and real-browser tests must prove the exact selected tagging mechanism, including nested/reentrant actions and delayed composition; extend only the narrow guarded adapter if public DOM tagging proves insufficient, with a concrete counterexample and upgrade checks. No broad monkeypatch or loss of genuine bytes is an acceptable fallback.

Notify listeners with an owned Uint8Array, then release it; do not retain a keyboard/paste history. An input emission up to the frozen inputQueueBytes ceiling is not silently truncated. Bound the adapter's own allocation before copying/encoding: use a fixed-cap UTF-8 encodeInto buffer with complete-read detection and a checked binary length. An over-ceiling emission produces no truncated prefix intent and reports INPUT_REJECTED through onFailure without invalidating the model; P3 surfaces this rejected action rather than recovering the view. P3 still owns aggregate input queue/epoch admission; V1 neither queues nor splits a rejected paste into later actions. No private input callback may allocate an unbounded observation log in production. Failure diagnostics contain fixed kinds and sizes only, never terminal text, clipboard text or credentials.

Publish focus before input for a genuine action requiring activation, so a ready spectator's first actual input can await the P3 grant rather than bypass authority. Increment a safe local focusSeq only for effective intent transitions/new deliberate activation; overflow reports COUNTER_EXHAUSTED and requires a fresh initialization. Do not count initialization, restore, output, theme, layout, show or backend replacement as user focus. Selection/copy and ordinary scrolling must not take control: a pointer-caused xterm textarea focus alone is not sufficient; a pointer action qualifies when it emits an actual provenance-qualified mouse/alternate-wheel intent, or the host explicitly activates the input target through P3. Keyboard/tab navigation and a real input action can activate. H1's explicit activation uses P3's input-target/focus API rather than relying on a selection click. Browser blur/hidden state may emit focused:false only for this view's previously effective input target; P3 checks its own current epoch. V1 does not decide who currently controls the server.

## Geometry, parsing bounds and failure policy

Construct with frozen max history 1000, fixed M0 font settings and the source's authoritative grid. Use the terminal's rendered cell dimensions plus container content box for measurement, with a guarded pinned DOM shape when necessary; keep that dependency confined to the geometry module. Never use a measured grid for baseline installation or observer fit. Two different-size containers must display the same terminal grid by clipping/scrolling/blank space, while reporting different valid proposals. The test page can inspect cells/modes to assert semantic rendering and a small screenshot can confirm clipping, but screenshots alone are not the oracle.

Bounds: at most one model, one <=64-KiB parse payload, one pending callback/timer, the fixed 1000-line history and descriptor counters. No whole-baseline duplicate or permanent raw-VT history. Check declared baseline maxima (8 MiB VT, 64 KiB tail, 129 chunks) and per-chunk/cumulative overrun before parsing. P3 owns metadata identity/ordinal/end and negotiated budgets; V1's defensive byte/count validation does not claim to validate absent metadata. Parser operation deadline is bounded by the existing 15-second recovery ceiling; P3 still owns transfer end-to-end deadline and cancellation. A timer is a hang guard, never a throughput SLO or an applied barrier. Use immediate rejection on invalid synchronous shape/state and one typed onFailure notification for the first fatal backend failure per incarnation; do not create a failure-notification loop when a listener throws.

Use existing safe `domainError` values: PROFILE_UNSUPPORTED for unsupported profile/version/surface; INVALID_SIZE for bad local geometry; BUSY for overlapping application; INPUT_REJECTED for the nonfatal input-size admission case above; RESYNC_REQUIRED for unusable local state/invalid transfer or forbidden baseline-required resize; RECOVERY_EXPIRED for the finite parsing/install deadline; RECOVERY_UNAVAILABLE for renderer/parser construction failure that cannot preserve the candidate. A failed operation rejects and, for fatal backend failure, emits onFailure from the same incarnation; P3 coalesces both paths with its operation/generation fence rather than comparing only kind/message or launching two recoveries. Expected deliberate disposal/reinitialization cancels pending work without publishing a new fatal failure; P3's existing operation fence handles the rejection. No new wire error kind or private error text is introduced.

Default rendering is xterm's existing DOM renderer; no WebGL addon, canvas renderer or extra native dependency is required for V1. A renderer construction/runtime failure cannot trigger an unbounded local rebuild loop. V1 reports failure once and retires that incarnation; P3 may recreate through its bounded recovery policy using a newer generation and a fresh authoritative baseline. No model export, local serializer replay, fake same-grid resize, forced application repaint or automatic PTY input is used to repair a failed view. If the newly constructed DOM renderer also fails, leave an observable failed view rather than repeatedly rebuilding it.

Context loss has a precise evidence boundary: this implementation owns no WebGL context, so adapter teardown/rebuild tests are not GPU context-loss tests. A future accelerated implementation must keep the parser model intact when an addon-only loss can fall back to DOM, permit at most a bounded attempt rather than a recurring retry timer, and otherwise signal the same failed-model replacement path. That is a future obligation, not a WebGL scaffold in V1.
