本文的 D1–D7、任务拆分与验收均为待审建议；尚未批准实施、选择依赖版本或启动原型。
规划与后续决定记录在 [#190](https://github.com/GhostFlying/cove/issues/190)。

M2 的正常双机 SSH/tsnet、双平台安装升级与实际 main CI 已通过；Linux 真实 systemd/logind

## 目标与已定边界

在 **macOS Electron、iOS/Android RN + WebView + xterm** 中完成相同核心工作流：
连接独立 server，管理 repo/task/workspace/mount/tab，操作和恢复真实终端。
Mobile 在 Desktop 完全退出后仍直接使用 server。macOS/Linux 是执行 server 的平台，
不把 Linux/Windows Desktop 加入首期，也不重开已接受的终端引擎与 VT 协议。

- Server 唯一持有 Git、文件系统、SQLite、PTY 与终端权威模型；客户端退出不停止 server/run。
- HTTP JSON-RPC 操作、业务事件 WebSocket、独立终端 WebSocket 分工延续现有设计。
- Desktop 支持已有 loopback、SSH、内嵌 tsnet；Mobile 首期内嵌 tsnet，SSH 后续评估。
  不依赖系统 Tailscale，不自动切换失败入口；使用通道对端身份及 serverId 核实后才发送凭据。
- Desktop 凭据由宿主使用系统钥匙串（M2 D5）；CLI 文件凭据保持自己的既有行为。
- focus、控制权与订阅分离；有效用户 focus 自动取得控制和尺寸，观察者不 resize。
  恢复、后台事件、其他设备切页不替本机选择页面，不自动重放不确定的输入或写操作。
- Desktop 按可见范围订阅终端；Mobile 默认仅当前终端实时订阅，其余用列表/快照。
- CLI 仍是完整 operator。新增事件和程序化输入提供同一领域语义的 CLI 路径。
  [#176](https://github.com/GhostFlying/cove/issues/176) 的 `tab send` 已排在 M2 之后，纳入本计划建议范围。

依据：[整体设计 §1](../design.md#1-已确认的产品边界)、[工程 §4](../engineering-plan.md#4-建议的里程碑与退出条件)、
[终端 §11.10](../terminal-architecture.md#1110-首版终端决策已确认)、[M2 D5/D9/D14](m2.md#已决策)。

## 待批准决定

以下均是推荐，**不是已选决定**。批准本文时逐项确认或修改；普通库版本/API 细节由实施者在所选边界内收敛。

### D1. Mobile 工程与 Go 承载

建议 Expo development build + prebuild/CNG，自有原生模块/配置插件，围绕现有 tsnet 语义提供小型 Go mobile wrapper。
采用 `gomobile bind` 的 AAR/XCFramework 与 Swift/Kotlin 接线作为先验证的路径，不使用 Expo Go。
仅证明这些工具存在，不声称现有 Go/tsnet 依赖图已经兼容。

备选为 bare RN，原生工程纳入版本管理。若 T0 证明 Go 接线无法简洁、完整地由 CNG 重建，
按该检查点回报证据并选择 bare RN，不进行无限框架比较。正式 UI 开工前验证：
两平台实际库/应用构建、节点登录、稳定 peer ID 核实、配对 RPC、终端 WS、取消/关闭和前后台重连。
不得把“库编译成功”当端到端可用。现成 libtailscale C 接口可作备选，但其 dial/status API 不自动证明
满足 Cove 的 WhoIs、登录持有与身份核实语义。

依据：[Expo development builds](https://docs.expo.dev/develop/development-builds/introduction/)、
[CNG](https://docs.expo.dev/workflow/continuous-native-generation/)、
[gomobile](https://pkg.go.dev/golang.org/x/mobile/cmd/gomobile)、[libtailscale](https://github.com/tailscale/libtailscale)。

### D2. Controller、view 与凭据的放置

建议 Desktop 的共用 Client/TerminalController 放 Electron main，Mobile 放 RN JS 宿主；
renderer/WebView 作为 bundled xterm view，使用有界、有 generation 的 view bridge。
凭据通过宿主安全存储提供，允许在受信任宿主 JS 内存中短暂使用；不宣称现有 CredentialSupplier 是 opaque handle。
显示文档不持久化 token、tsnet 状态或待重发输入。

收益是沿用一套控制器且视图重建不制造第二个输入队列；代价是 VT 与解析完成需跨桥，必须先证明：

- baseline/event 的 Promise 在 view **实际应用完成**后确认，不能以消息已 post 代替解析完成；
- 单一有界队列、字节 credit、取消/失败/销毁结算；旧 view generation 的数据和 ACK 不影响新 view；
- `measureGrid()` 当前同步：proxy 只返回当前 generation 已确认的几何缓存，initialize/有效 focus 前先完成测量；
  若必须改共享接口，由同一契约 writer 先审清影响，消费者不各自改签名；
- Native HttpPort/TerminalPort 保留 not-sent/handed-off/unknown、接收上限与取消语义，不把发到桥上等同远端已执行。

备选是 renderer/WebView 内运行 Client/Controller、宿主仅提供网络/凭据或窄 loopback 通道：
少一次 view 桥，但需明确 token 进入可信显示运行时的内存，以及本地通道身份/生命周期/平台网络规则。
若实测主路径的桥成本不能满足前台使用，凭证据再选备选；不先重写原生终端控制器。

### D3. Desktop 节点与本机首次使用

建议同一 OS 用户及 Cove home 的 Desktop/CLI 复用 M2 D14 常驻 dial **网络节点**，
Desktop 保留独立设备注册和钥匙串 token；不读取 CLI token 文件作回退。
节点共享可减少 Tailnet 节点与重复登录，但 CLI 显式 logout/stop 的影响必须覆盖 app 活动流，GUI 如实显示断开。
helper 使用独立稳定位置与既有版本兼容/影响检查，不能因 app 退出或清理临时构建目录破坏其他客户端。
备选是 Desktop 独立节点，生命周期更分离，代价是额外节点、登录与命名。

本机建议首版连接已通过 CLI 独立安装的 server；缺少安装时提供准确命令与可恢复说明。
GUI 为本机 server 创建自己的设备授权，常规操作与远端使用相同凭据/RPC；本机所有者秘密仅用于显式 bootstrap。
备选是 M3 增加明确的 GUI 安装/启动按钮，复用 M2 领域操作与影响确认；不会在打开 app 时自动安装或替换运行服务。
普通 repo/task 等操作不能通过执行 CLI 子进程代替共用领域客户端。

### D4. 业务事件、快照与断线恢复

建议单实例内的有界内存事件窗口 + 一致快照/cursor；重启、缺口或超窗显式要求重新取快照。
备选持久事件表/outbox 支持跨重启历史，需数据库迁移与额外交付语义，本阶段建议不选。
这不改变 durable operation 去重记录，也不承诺完整历史事件审计。

- 快照与 cursor 必须形成真实屏障，多页必须来自同一视图或明确重取；已有列表分页 token 不是事件 cursor。
- cursor 绑定 server/instance/stream generation。订阅要么完整交付快照之后的相关变化，要么明确失效；不能静默从现在开始。
- 变化发布于持久提交/已确认运行事实之后，覆盖后台操作和 run 退出，不只拦截 RPC 返回。
  提交到通知间发生不确定失败时，失效相关订阅并要求重取，不能靠递增 cursor 掩盖漏发。
- 定义删除、归档、过滤、旧连接/旧 revision、慢消费者溢出语义；过滤掉的序号不能被误判为丢失。
- 业务 WS 与 PTY 字节流分开，复用已有鉴权、撤销和通道身份；UI 镜像断线时标为陈旧/不可核实。
- CLI 建议提供单一 `cove events --json` 只读入口及筛选/cursor；快照帧与退出码由契约 writer 定义，同步 tend 文档。

这是对 [Server 架构 §3](../server-architecture.md#3-同步命令提交给-serverserver-发布事实) 未定机制的选择建议，
不是宣称事件能力已经实现。

### D5. Mobile 凭据与前后台

建议设备 token 使用 iOS Keychain / Android Keystore-backed 安全存储（Expo 路径可用 SecureStore），
tsnet 完整节点状态另放 app 私有原生目录，使用平台数据保护并排除不合适的备份；不假设小型 secret store 可装整个状态文件。
不提供明文 fallback。持久化失败不得显示配对成功；兑换响应丢失沿用 M2 新邀请流程。

建议前台优先，不承诺 app 后台常驻网络。后台撤去 focus 意图并暂停显示，容许 OS 暂停/终止进程；
远端 PTY 继续。前台恢复网络、入口核实和 view 基线，不以恢复动作抢控制或重放输入。
tsnet stop、Tailnet logout、忘记 Cove server、撤销设备分别表达，不能混同。
备选后台服务/VPN 扩展会增加平台能力与交付范围，本阶段建议不选。

依据：[SecureStore](https://docs.expo.dev/versions/latest/sdk/securestore/)、
[Apple 后台执行](https://developer.apple.com/documentation/uikit/about-the-background-execution-sequence)、
[Android 进程生命周期](https://developer.android.com/guide/components/activities/process-lifecycle)。

### D6. 首批支持与验收矩阵

建议候选下限：macOS 14 arm64、iOS 16 arm64、Android 12/API31 arm64；首轮各一台代表设备，
移动端最终验收用物理机，至少一台覆盖外接键盘。候选是范围建议，尚未证明依赖兼容或作出支持承诺。
T0 按所选 Electron、RN/Expo、WebView、Go/SDK 的实际要求固定兼容组合与准确最低版本；
若候选下限不满足，带选兼容栈/提高下限的影响返回用户决定，不能静默变更支持矩阵。
macOS x64 或更旧移动系统若是首期需求，在批准时选入并计入构建/验收成本。
Electron 用 electron-vite、RN 用 Metro、terminal WebView 资源用 Vite 随 app 打包；不运行时依赖 CDN。
正式安装器、签名/公证、商店发布、自动更新仍属 M4；M3 需真实可运行 app 与可重复的开发/测试构建。

### D7. 普通命令活动状态

已接受的执行中/近期/闲置方向保留。当前 lifecycle/verification 仅说明 run 与可核实性，
不能代替 shell 命令状态；PTY 存活、Enter、安静输出均不能证明 busy/idle/完成。
建议首版 GUI 显示现有真实 run 状态，对无可靠活动信号显示 unknown；**shell integration 延期需用户明确接受**。
备选是在 M3 增加独立 T8：受支持 shell 的开始/结束/prompt 观测、server 分类/配置、CLI 与两端显示，
对未支持 shell、嵌套 SSH/tmux 或失效观测降级 unknown。T8 增加共享 protocol/server/worker 范围，不能塞进 UI 实现。
Agent 最后业务状态仍归 tend，普通 shell integration 不变成 agent hook 项目。

## 最小可用工作流

1. 添加多个 server、粘贴邀请配对、显示入口/身份/连接错误；Desktop 选择 SSH/tsnet，Mobile 使用内嵌节点。
2. 按执行 server 注册 repo，创建 checkout 或独立 worktree、多仓 task；新增/移除/转换挂载、归档/恢复任务。
   展示逐仓部分结果、pending/revision 冲突及缺失路径；远端路径不使用手机/笔记本目录冒充。
3. 创建和选择 tab，输入/粘贴/滚动/选择复制、停止、查看历史、显式重开；关视图与停止 run 是不同操作。
4. 操作结果未知时保存原 operation 身份并查询；重连/重启/恢复不暗中重做创建或输入。
5. 另一设备的列表变化和控制事实可见，本机导航与 focus 保持本地；展示 run 生命周期、核实状态、连接、控制与活动来源。
6. 查看设备、显式撤销/忘记与必要配对交互；通用设置 UI、编辑器、Git review 面板不作为首版前提。

## `tab send` 的既有决定与交付

沿用 [设计 §7.1 模型 A](../design.md#71-以-tend-实现-shepherd经-cli-集成方向已接受未排期)，不重开抢控制策略。
`operationId + serverId/runId/relayInstanceId + 观测 epoch + 内容/可选 submit` 构成不可变执行意图。
先查去重记录，再对新请求检查确切存活 run、无人控制和相同 epoch；不转投重开后的 run，不 focus、不 resize。
runtime/worker 与人类控制权共用串行顺序；排队后 epoch 变化也要拒绝过期输入。
任一 send 未完整写入时，后续尚未写入的依赖输入前缀封闭失败；submit 仅在文本完整确认后发送，独立报告。
成功/拒绝/部分写入/unknown 保留真实前缀和 unknownBytes；未知/部分结果不自动重发，重启遗留 send 仅核实或放弃。

建议 CLI canonical 名为 `--if-control-epoch`，与 #176 一致；设计中的 `--control-epoch` 只是未发布示例，
实现 PR 同步示例及 tend changelog，不预建兼容 alias。数据大小、记录上限和准确 JSON/退出码在 T6 契约中定案。
`tab get` 增加准确 run 的控制者/epoch 观测，不能为查询而创建 focus subscription。
