## 交付范围

在 macOS/Linux 上运行独立 Node server、CLI 和一个浏览器终端页面，连接同一个真实 PTY。
所有客户端断开后 PTY 继续存活。仅本机 loopback、每次启动的短期凭据；持久化属于 M1，
设备配对/远程接入属于 M2。不实现 task/workspace、SQLite、keeper、tsnet、迁移、chat、
定时任务、Shepherd 或 agent hook。

已合入的 protocol、terminal-engine、terminal-worker、server、client、terminal-web
保留现状；不为 M0 继续加深其证明性测试，也不在没有实际问题时重构。

## 验收场景

每个场景是一个启动编译产物（server/CLI/浏览器页面）的自动化测试，在 macOS 与 Linux
CI 上运行，结果只有通过或失败。CI 绿灯就是证据，不另行封存。

| ID  | 场景                                                                                                               |
| --- | ------------------------------------------------------------------------------------------------------------------ |
| S1  | CLI 创建终端，输入命令得到输出；进程退出后状态为已退出并带退出码。                                                 |
| S2  | 所有客户端断开后重新 attach，PTY 仍在运行且可继续输入。                                                            |
| S3  | 两个客户端轮流 focus，PTY 尺寸跟随当前操作者；旁观者和持有过期控制权的客户端输入被拒绝。                           |
| S4  | 终端查询（如 DA/CPR）只由 server 回复一次，包括没有客户端连接时；客户端不写回自动回复，同时真实键盘/粘贴输入不丢。 |
| S5  | 断线重连后通过基线加增量恢复，画面与 server 模型一致，不丢不重。                                                   |
| S6  | 在 alternate screen 中（如 vim/less 打开时）断线重连，画面正确；退出后回到 normal buffer 也正确。                  |
| S7  | 慢客户端积压超限时 server 退役其订阅（RESYNC_REQUIRED），健康客户端持续收发；慢客户端随后取新基线继续。            |
| S8  | 协议版本不匹配时，HTTP RPC 与终端 WebSocket 两个入口都在业务操作前以明确的协议不匹配错误拒绝，且不影响已有 PTY。   |

PTY 到服务端模型的解析背压与有序性由已合入的 worker 测试覆盖，继续随 CI 运行，不另设 M0 门槛。

另需用户在 M0 测试 harness（`cove server start --harness`）上做约一小时的集中试用，
用自动化场景覆盖不到的真实 TUI 负载检验终端链路：

- 分别启动 Codex、TraeX、Claude Code，正常交互一段时间；
- 关闭并重开浏览器标签页，会话仍在、画面正确；
- 两个标签页轮流操作同一终端并调整窗口大小；
- 在 vim/less 中断线重连。

发现的问题修复后再提交阶段 review。harness 只是 M0 测试载体，不是二期 Web App
或 M3 的 Electron/RN 客户端。性能数据（延迟、CPU/RSS）可记录，但不作为 M0 门槛。
