## 交付范围

在 macOS/Linux 上运行独立 Node server、CLI 和一个浏览器终端页面，连接同一个真实 PTY。
所有客户端断开后 PTY 继续存活。仅本机 loopback、每次启动的短期凭据；持久化属于 M1，
设备配对/远程接入属于 M2。不实现 task/workspace、SQLite、keeper、tsnet、迁移、chat、
定时任务、Shepherd 或 agent hook。

已合入的 protocol、terminal-engine、terminal-worker、server、client、terminal-web
保留现状；不为 M0 继续加深其证明性测试，也不在没有实际问题时重构。

## 验收场景

每个场景是一个启动编译产物（server/CLI/浏览器页面）的自动化测试，在 macOS 与 Linux
CI 上运行，结果只有通过或失败。CI 绿灯就是证据，不另行封存。

| ID  | 场景                                                               |
| --- | ------------------------------------------------------------------ |
| S1  | CLI 创建终端，输入命令得到输出；进程退出后状态为已退出并带退出码。 |
| S2  | 所有客户端断开后重新 attach，PTY 仍在运行且可继续输入。            |
| S3  | 两个客户端轮流 focus，PTY 尺寸跟随当前操作者；旁观者不改变尺寸。   |
| S4  | 终端查询（如 DA/CPR）只由 server 回复一次；客户端不写回自动回复。  |
| S5  | 断线重连后通过基线加增量恢复，画面与 server 模型一致，不丢不重。   |
| S6  | 进入并退出 alternate screen（如 vim/less）后，重连画面正确。       |
| S7  | 慢客户端积压超过上限时被 server 断开，重连后能取新基线继续。       |
| S8  | 协议版本不匹配时在任何业务操作前被明确拒绝，且不影响已有 PTY。     |

另需用户用 Codex、TraeX、Claude Code 在 M0 链路上实际工作一天；发现的问题修复后
再提交阶段 review。性能数据（延迟、CPU/RSS）可记录，但不作为 M0 门槛。
